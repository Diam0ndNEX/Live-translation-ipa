# ScreenLingo 2.2.1 – addendum (2026-11-08)

Four findings that were reported in the review but were missing from `v2.2.1-specification.md`. They are part of 2.2.1, use the
same rules (spec §1, no frozen areas, contract assertions updated deliberately and named) and the same table format.
Anything not proven is marked **unverified**.

| ID | Sev | Finding (evidence) | Fix | Verify | Package |
|---|---|---|---|---|---|
| E15 | P2 | **History is written to disk on every caption, on the main thread.** `TranslatorEngine.history` has `didSet { saveHistory() }`. `show()` does `history.insert(...)` and, at the limit, `history.removeLast()`, so the whole list (up to 1,000 items) is JSON-encoded and written to UserDefaults once or twice per caption. Each UserDefaults write also fires `PresetStore`'s `didChangeNotification` observer. Same pattern as the Library-notes bug fixed in 2.2.0. Verified for the code path; the time cost is **unmeasured**. | Do the insert and the trim in one mutation (one write). Debounce `saveHistory()` (about 1 s) and flush at once on: app to background, delete, star/unstar, import, erase, and `saveHistory` off. Add a distribution `historySaveMs` to the diagnostics so the cost is visible. Do E1's trimming helper in the same commit (same function). | Swift test: ten inserts inside one second cause one write; flush on background. Report shows `historySaveMs`. **Device check.** | WP1 |
| E16 | P2 | **The light/dark setting is not in the backup or in Reset all.** `InterfaceSettings` stores `appearance` and lists it in its own page reset, but `TranslatorEngine.settingKeys` (`presetKeys + interfaceKeys`) does not contain it, so `exportSettings`, `importSettings` and `resetAllSettings` skip it. Verified for the lists. Confirm which key `ThemeStore` reads before changing anything (`ThemeStore` was not read). | Add `appearance` (default `system`) to `interfaceKeys` and `defaults`. Check `accent` is already there (it is). Update the key-ownership script if it lists keys. | Export JSON contains `appearance`; Reset all returns it to System. | WP4 |
| E17 | P1 | **"Open the floating window when capture starts" only works while ScreenLingo is still in the foreground.** `TranslatorEngine.handle()` opens the window on the first packet only if `UIApplication.shared.applicationState == .active`. If you have already switched to your video app, nothing opens, the session shows the amber "Floating window is closed" state, and nothing says why. Verified for the condition; how often it happens is timing-dependent (**unverified**). Since 2.2.0 the Start button no longer opens the window either. | (a) Change the setting's label and footer: "Opens the window when capture starts, only if ScreenLingo is still open." (b) In the amber `windowClosed` state show the existing "Show window" button prominently with the hint "Open it before you leave the app." (c) Record a runtime event `pip_auto_open_skipped_not_active` so a run explains a missing window. (d) When the app becomes active again with capture alive, no window, and the setting on, call `startPiP()` once. | Source contract for (a)-(d); fixture `attention-window-closed`. **Device check.** | WP4 |
| E18 | P2 | **Legacy can run a synthetic translation during live capture.** In `tick()`: when capture is alive, not paused, no text for more than 8 s and the last warm-up is older than 25 s, `prewarm()` runs. Its Legacy branch skips only if `directSession` already holds a session for the pair; with `legacySharedSession` on, the idle session may be lent out instead of stored in `directSession`, so the guard can pass and a warm-up model call runs beside live work. That is an extra Apple Default call that can delay the next real caption (the analysis already shows a model-switch penalty in Hybrid; Legacy has `legacy_confirmed_after_switch` for exactly this). **Unverified effect.** | Add the evidence first: count warm-up model calls that start while capture is alive (`warmup_started` during a run) and print the number in the report's Legacy line. Add Advanced setting `liveWarmupLegacy` (default **on** = today's behaviour) so a run with it off can be compared on one install (same mechanism as D13; value goes into `settings` and the cohort keys). No behaviour change by default. | Report shows the count; setting recorded. **Device check:** compare Legacy with it on and off. | WP6 |

## Corrections to the main spec

- §4 cohort keys: add `liveWarmupLegacy`. D4 settings allowlist: add `liveWarmupLegacy` and `appearance` is **not** exported (interface-only), but must be in backup and reset (E16).
- §5 package contents: WP1 also does E15; WP4 also does E16 and E17; WP6 also does E18.
- §9 checklist: add "E15-E18 fixed or listed under Not done".

## Reported earlier and intentionally not a fix

- Translate and Tune "Speed" reach the extension within seconds without a flush: covered by E5, no extra work.
- Identical-frame holds differ between Legacy and Hybrid/Low Latency: counter only (E9).
- Memory-store save/health cost and lookup waits: measurement only in 2.2.1 (D10); the second reader is the next update.
