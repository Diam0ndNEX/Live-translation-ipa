# ScreenLingo v1.4.1 — Diagnostic ZIP acceptance and interpretation

## User problem reproduced in three build-44 diagnostics
- Automatic vs Balanced did not produce a meaningful decrease in experienced subtitle delay.
- A second Balanced run with **Skip unchanged frames OFF** and **Reduce OCR work while idle OFF** still missed or cancelled rapidly changing subtitles.
- Static HUD/overlay text may dominate Movie-mode OCR block selection; this is a *code-supported hypothesis*, not confirmed user-video ground truth.
- The old export kept only a recent event ring (now 2,400), and measurement started at the first recognized OCR sighting. A caption missed before OCR does not appear in that latency distribution.

## What the new ZIP contains
- `session.json`: app/build, iOS and device hardware family, allowlisted recognition and power settings, translation-memory health, session counters, bounded recent/early structured events, distributions, and optional `intervals`.
- `intervals.csv`: up to 960 chronological **15-second** windows. Data includes captured-frame and OCR-pass deltas; OCR, recognition and enqueue timing summaries; unchanged/cadence/paused skips, empty OCR passes, confidence-independent motion counts, thermal level/Low Power Mode, whether capture is connected, model warm-up/batch activity, memory origins, candidate confirmation/supersession/queue overwrite/enqueue outcomes and the Movie text-selection override counters.
- `README.txt`: limitations, units, privacy and how to interpret event counts.

### Important definitions
- `visual_motion_proxy_ms`: difference between a sampled **coarse visual image change** and OCR first sighting. Moving background scenes, animation and UI changes may cause the difference; it is **not** true subtitle acquisition latency.
- `candidateConfirmed`, `candidateFirstSeen`, `candidateSuperseded`, `candidateEnqueued` and cancellation are **events, not distinct spoken sentences**; a candidate can have multiple events, and unobserved subtitles cannot be counted.
- `enqueue_median_ms` and `enqueue_p95_ms` stop at PiP sample-buffer enqueue. Physical screen presentation is not instrumented by the app.
- The `ocr_median_ms` distribution measures OCR execution times **after OCR is scheduled**, not skipped video time.
- `effective_ocr_interval_ms` is the last applied **configured** interval after adaptive/idle effects for that window; it is not observed frame latency.
- `model_batch_median_ms` measures installed translation session batch calls when supported; model work completed inside the legacy hosted translation path is not fully covered.
- The last available interval may be shorter than 15 seconds; if iOS suspends the app, the interval may cover a much longer elapsed wall time without samples. Blank percentiles mean insufficient samples.
- Windows are capped at 960 (~4 hours), and their metrics are summarized. Old v1.4.0 ZIPs have no intervals and still decode normally.

## Device acceptance matrix
1. **Cold startup**: start new capture, do not display any subtitles for 10 seconds, then display rapid subtitles. Confirm startup events survive a 20-minute session.
2. **Static-overlay test**: show persistent large UI text and small changing dialogue in Movie mode. Confirm `movieSelections`, `movieTemporalOverrides` and `movieRejectedSmall` advance where appropriate; compare actual output visually.
3. **Recognition toggles**: repeat the same segment with skip unchanged + idle backoff both ON vs OFF. Verify exported settings and `effective_ocr_interval_ms`.
4. **Confirmed cancellation**: rapid 0.5–1s subtitles. Confirm the ZIP can distinguish rejected early sightings, confirmed-but-unpresented, replacement queued, model completion and PiP enqueue.
5. **Warm/thermal test**: long playback on battery, inspect timed 15-second windows for OCR cadence and thermal transitions. No CPU watts or internal iOS temperatures are implied.
6. **Memory fair A/B**: use built-in Fresh translation test (in v1.4.1), do **not** erase saved SQLite data; compare model timing separately from OCR pickup and physical presentation.
7. **Disconnect / resume / background**: verify the gap and capture-state transitions; do not interpret missing samples as successful OCR.
8. **Privacy**: ZIP must contain no source OCR words, translations, screenshots, source filenames, cache keys or private transcript data, even if include-text UI options are enabled.
9. **Upgrade**: install signed IPA on top of prior build; verify retained preferences, history and SQLite memory. Re-test import and restore.
10. **CI**: pipeline tests, SQLite memory suite, diagnostic archive privacy and ZIP interoperability, Xcode iOS build + IPA metadata must pass.

## Release caveats
This is **diagnostic instrumentation**, not a claim that OCR now recognizes all captions. A video clip or deliberately user-supplied screen recording remains necessary to know exactly which text the app should have shown. A privacy-preserving telemetry export alone cannot reconstruct invisible text. These acceptance tests require a signed iPhone IPA and remain unverified until actually performed.
