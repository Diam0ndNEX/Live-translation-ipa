# ScreenLingo v1.4.4 — subtitle continuity and model performance acceptance

## Why this release
Comparative 1.4.2/1.4.3 five-minute video diagnostics showed very high RAM/SQLite reuse and normal temperature, yet measurable early-session first-use model costs and end-to-end tail latency above one second. The new 1.4.3 idle validator is a separate subsystem and should not run during capture.

## Implemented changes
1. **Predictive on-device model warm-up (opt-out):** In Auto mode with unresolved current source, an earlier actually displayed source from the previous 24 hours can prepare an installed translation session. Auto-language recognition is *not* overridden; a new detected language or explicit source always wins. The startup warm-up task is canceled on live capture connection. Cold-session diagnostic events and actual warm-up status distinguish guesses from confirmed source.
2. **Confirmed subtitle continuity (opt-out):** If a new confirmed caption arrives while earlier confirmed work is still running, protect the earlier result for at most 450 ms; keep only the newest candidate and replay it after presentation or processing finishes. Stale pending replacements expire after 1.2 s. All other freshness/rotation/text-specific invalidation still applies. This is not a guarantee that no subtitle is ever missed.
3. **Adaptive speculation (opt-out):** Once at least 24 speculative jobs have been attempted and low usefulness/high discard are observed, throttle alternate tentative opportunities, never confirmed work. Recent speculative efficacy can recover without a permanent blackout. Existing confidence, thermal, power and cache policies remain in effect.
4. **Performance diagnostics:** Separate first-30-second model batches, predictive warm-up and its preemption, deferred confirmed handoffs, adaptive speculative skips, and OCR-first-sighting → PiP-buffer enqueue events over 1,200 ms. No physical on-screen presentation measurement is claimed.
5. **Memory-validation diagnostics:** Include only aggregate number selected, committed, skipped, peak workers and wall-clock duration in the diagnostic ZIP; preserve the v1.4.3 interactive progress, rate, ETA, cancellation and SQLite transactional safety.
6. **User controls:** Performance and Smart Pipeline pages expose switches and reset behavior for predictive warm-up, adaptive speculative throttling and the short confirmed-caption handoff. Defaults are enabled; turn off individually to compare against v1.4.3.

## Release checks
- Swift pipeline regression tests: exact/genuinely changed subtitle replacement; no tentative-to-confirmed promotion; 450 ms bound; no indefinite stale candidate replay; speculative policy begins only after adequate evidence; prior source never changes current Auto OCR language.
- Memory migration/rollback, diagnostics privacy allowlists, large-DB benchmark, full Release iOS application + extension build, version 1.4.4 build 48 in both bundles, IPA packaging.
- Device acceptance: five-minute **same video**, identical Movie/Balanced/OCR settings, memory hit-origin and memory-db size controlled, diagnostics ZIP exported. Include **fresh translation test** on a shorter comparable clip to separate cache benefit from true model speed.
- Compare median/P90/P95 and worst first OCR → PiP enqueue, first-30s model request distribution, confirmed unpresented supersessions, speculation attempts/benefits/discards, thermal and write failures. A performance improvement is not proven until these measurements exist.
- Keep main untouched; PR based on v1.4.3 branch. Preserve on-device memory, history, privacy, and existing iOS 18 hosted translation fallback.

## Operational limitations
iOS TranslationSession performance, cancellation timing, OCR accuracy and physical display latency cannot be established from a successful CI build. Model warm-up is best-effort, can be deferred, and may not improve an unrelated next language. When diagnostics are off, adaptive speculation has insufficient counters to enter a throttle and behaves as the original selective speculative policy.
