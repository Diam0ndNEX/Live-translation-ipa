### What the baseline can and cannot show

The build 90 views read `TranslatorEngine` directly, so a fixture can only open a tab or sheet; it does not fake
engine state (that would mean writing into the engine). In the baseline:

| Fixture | Baseline shows |
|---|---|
| idle, idle-pack-missing, starting, live-short, live-long, paused, attention-lost | Live tab, idle (pack state is whatever the simulator reports) |
| library-empty, library-many | Library tab, empty (fresh simulator) |
| diagnostics-idle, diagnostics-live, diagnostics-bad | Diagnostics tab, idle |
| settings-root, settings-caption | Settings root (sub-page push not routable in build 90) |
| languages-sheet | Languages tab (it is a tab in build 90) |
| onboarding | Onboarding cover (`-onboarded NO`) |
| area-editor | Live tab with the Capture area sheet |

From step 2 on, the 2.1.0 views read snapshot structs, and each state fixture injects its own snapshot, so
`live-short`, `paused`, `library-many` and the others show their real states without starting capture.
