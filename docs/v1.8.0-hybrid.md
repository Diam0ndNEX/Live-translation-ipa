# v1.8.0 (64): hybrid low-latency + Apple-default translation

## User-visible behavior

Settings → Translation & memory → Translation models offers High fidelity,
Low latency and Hybrid · fast then refine. Existing low-only preference survives;
new hybrid selection starts OFF so older comparison cohorts and user choices do
not change silently. Both model options are core controls, no longer buried in
Experimental Features. iOS 26.4+ is required for explicit model strategies.

Hybrid uses compatible complete compatible memory immediately. Missing live
units can be translated by the low-latency model during tentative OCR. After
ordinary OCR confirmation, a complete fast caption can appear. The Live tab labels it Fast preview. Apple’s default strategy then translates its missing units through the normal
quality pipeline. Its complete result replaces the preview without clearing it.
A newer subtitle can supersede an old refinement; stale results cannot present.
A refinement of the same caption does not wait out its own preview's readability hold.
If a newer confirmed caption already waited during the fast request, a successfully
shown preview yields the model lane to that handoff before starting obsolete quality
work. Every successful render, including previews, updates the PiP self-reading
fingerprints before tier-specific early returns.

Quality and preview model calls remain serialized in the existing drain. No detached
or competing model work is introduced. Partial captions are never shown. Power-saving,
non-nominal thermal state, fresh-only comparison and manual photo/text work use the
quality-only route. Missing or unsupported low-latency packs also fall back to quality.
Live work never prompts for a download; Prepare fast language packs is an explicit
user action for the selected source/target pair.

Hybrid does not force high fidelity: it omits preferredStrategy for the primary
route and lets Apple choose the default. Low latency remains explicit. Apple default
is not a third model, and this does not guarantee two distinct underlying models
on every device, OS, SDK or language pair. The preview-then-refine presentation
behavior is unchanged by this strategy correction.

## Memory and side effects

- Preview results use a separate, bounded 256-unit LRU type, never the quality RAM
  bank, SQLite writer, saved history, automatic clipboard or speech path.
- Normal and temporary preview caches are independent and process-only. Successful
  speculative exits also enforce the configured quality-RAM eviction budget. Language,
  rule and protected-name compatibility is carried by the existing exact unit key.
- Hybrid quality output preserves normal Apple-default v4 keys and rule digest.
  Pure low-only output retains its existing isolated strategy digest. A conflicting
  imported low-only flag cannot cause hybrid default-strategy results to use low keys.
- Full-caption assembly, protected names, glossary and generation/context guards
  are shared by both display tiers. Only the final tier reaches normal side effects.
- Completed obsolete preview units can seed only the same compatible preview cache;
  context/mode/rules changes reject them. Routine cancellation preserves usable warm
  handles; context invalidation permanently retires the preview session.
- Preview enqueues do not count as ordinary final enqueues or final timing samples.

The write-admission recovery fix from build 62 is included. Database schema, location,
canonical key generator, durable writer and existing data are not migrated or reset.

## Evidence and acceptance

Diagnostic ZIP exports:
- hybridFirstEnqueueMs: first visible full result, including quality-memory hits.
- hybridFinalEnqueueMs: Apple-default final enqueue, independently measured.
- hybridLowModelMs: completed low-model API durations.
- Hybrid low batches/failures/unavailability, preview/final enqueues, cache hits and
  superseded refinements. Starting hybrid-preview population is separate from the
  starting quality RAM population.

The old single-model comparison rejects mismatched hybrid mode or preview populations.
`compare_hybrid.py` explicitly compares hybrid with an older Apple-default baseline:
all first-visible median/mean/P90/P95 targets must improve by 25% in temporary mode
(or 10% in normal mode), all final-quality statistics must be no worse, both strategy
paths must actually execute, memory/reliability must hold, and independent wording,
flicker, workload, upgrade and bank-isolation evidence is mandatory. A quick preview
cannot hide missing, slower or superseded quality refinements. These targets are not
a measured result; device speed, appearance, final quality and power remain unverified.

Tests cover preview LRU/bank isolation, strategy-key precedence, policy fallbacks,
complete-caption assembly, archive privacy/separate distributions and strict hybrid
comparison vetoes. Final code commit `0a887e7804af6b9fd1498dbcf479d697c32d16ce`
passed the full [build 63 workflow](https://github.com/Diam0ndNEX/Live-translation-ipa/actions/runs/40839429036).
Pipeline, asynchronous scheduler, SQLite migration/admission recovery, capture transport,
diagnostic privacy/correlation, storage scaling, settings and acceptance-gate checks

   translations. Verify that the prior saved-memory population remains available.
2. Select Settings → Translation & memory → Translation models → Hybrid · fast then
   refine, choose an explicit language pair, and prepare its fast language packs.
   Retain the same Balanced, OCR, stability and speculation settings as the baselines.
3. Record the same video boundaries in normal and temporary mode separately, with
   at least 50 final captions in each recording. Terminate and relaunch before each
   run so both starting quality RAM and starting preview-cache populations are zero.
   Preserve disk memory. Match device, OS, languages, content and thermal conditions.
