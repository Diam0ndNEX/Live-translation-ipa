# ScreenLingo v1.9.4 — measured reliability candidate

## Release decision
v1.9.4, NOT v2.0.0. No measured evidence supplies at least 90% confidence that a performance rewrite would improve Legacy, Hybrid Recovery, and Low Latency simultaneously. Do not claim universal performance improvements from this candidate.

## Device baseline (30 October 2026)
Three uploaded Portuguese → English Balanced / Temporary Memory diagnostics (the app metadata reports v1.9.3 build 74):

| Mode | median OCR→PiP enqueue | mean | P95 | successful enqueue samples |
| --- | ---: | ---: | ---: | ---: |
| Legacy | 550 ms | 574 ms | 1,017 ms | 89 |
| Hybrid | 382 ms | 542 ms | 1,409 ms | 77 |
| Low Latency | 232 ms | 281 ms | 442 ms | 84 |

These are observations, not performance promises. An enqueue is not physical screen presentation. Tests were not perfectly matched for cache snapshots, thermal chronology, or subtitle frequency.

## Implemented in this candidate
- Version and build synchronized to v1.9.4 (75) for app and extension, with changelog and matching source-contract tests.
- Count real warm-up model submissions as warmupAttempts and successful completed warm-up operations as warmupSucceeded in the common Diagnostics counter stream, regardless of the selected pipeline. Failed or skipped claims do not produce success counts. Preserve separate per-strategy duration metrics, retained warm-up event trace, and warmupModelBatches.
- Add regression assertions for the common warm-up event wiring.
- Reduce the confirmed-request backend lane handoff polling interval from 20 ms to 5 ms for Hybrid and Low Latency when the previous real Apple request is still draining. Speculation still rejects busy-lane admission immediately; timeout/cancellation and session ownership remain unchanged. This is a small targeted queue-wake optimization, not a measured end-to-end speedup.\n- Preserve the Legacy scheduler, persistent memory schemas, temporary-memory rules and PiP result selection. Do not claim speedup without iPhone evidence.

Specifically measure overlap with Low Latency recovery and cancellation-to-actual-return.\n\nLow Latency: profile OCR→confirmation, PiP enqueue, predicted-text reuse and duplicate suppression. Preserve current 45 ms speculative model median and 232 ms end-to-end median as regressions gates. Any optimization should first be an opt-in benchmark candidate rather than a wholesale rewrite.\n\n## Additional implemented changes (all three modes)
- Shared Movie OCR confirmation scheduling now uses a 100 ms minimum between independent reads when the measured OCR service time permits, instead of 120 ms. Same confidence, read count and image detail; nominal Movie only, never under pressure/Cool mode. The improvement is a maximum of 20 ms per such confirmation interval, not a guaranteed 20 ms end-to-end win.
- Legacy can immediately present a fully reused exact RAM caption whether the model lane is idle or busy. Explicit source selection and exact caption/rules keys are required; automatic source detection retains the normal pipeline.
- Legacy in-flight unit matching snapshots text-cleaning, slang and speaker preferences once per candidate.

## Same-fingerprint Apple Default comparison
The overall speculative-service median differs (standalone Legacy ~251 ms, Hybrid ~511 ms from whole distributions), but four subtitle fingerprints observed in both modes had matched samples of 270/261, 192/197, 211/209 and 194/232 ms (Legacy/Hybrid, respectively). These matched results do **not** indicate an intrinsic 2x Apple Default cost for identical content. Only four samples match, and differences in request mix, late-session competition, cache state and model resource ownership remain open questions.

## Build 76 — universal capabilities for every preset

The built-in Movie, Lyrics, Game, and Comic categories no longer unlock or prohibit runtime recognition algorithms. Instead every preset (including imported and user-defined presets) has the same three independently stored settings under Reading & OCR → Text behavior:

| Setting key | Feature | Movie/Lyrics default | Game/Comic default |
| --- | --- | --- | --- |
| rapidTextTracking | Responsive confirmation cadence, idle OCR and unchanged-frame polling | On | Off |
| joinAdjacentText | Adjacent subtitle-word grouping and overlapping duplicate removal | On | Off |
| activeTextFocus | Rank and follow the active caption/text group | On | Off |

The existing optional preserveRelatedMovieGroups feature is no longer disabled outside Movie; it is useful in any preset with activeTextFocus enabled. Its behavior is unchanged when focus is disabled.

A one-time non-destructive preference migration seeds these three switches from each user's prior mode only when values were absent. Importing or selecting an older custom preset that has no new keys likewise inherits its prior category's values. Newly saved custom presets persist all three explicit settings. Reapplying built-in presets sets them explicitly and does not force other unrelated settings. The legacy mode string is still stored for compatibility and for preset category display, but cannot gate recognition code. Cross-app Config retains the old movieMode field as a backwards-compatible alias; the extension prefers rapidTextTracking when present.

Tests assert that both fast OCR and grouping work independently of mode categories and that a previously saved Game profile retains its prior behavior. Static Settings tests reject reintroducing the disabled-in-non-Movie experimental control.

These changes require a fresh IPA and controlled device benchmarks; the successful build-75 IPA predates the preset refactor.

## Next engineering investigation (not implemented)
Hybrid retained-session Low Latency recovery has approximately 47 ms median but 1,568 ms P95 service, while standalone Low Latency speculative service is around 45 ms median / 64 ms P95. Prioritize tracing physical backend lane occupancy, cancellation-to-return, default speculation overlap, and whether simultaneous strategy sessions compete for internal translation resources. Do not confuse software queue waiting with internal backend service time.

Instrument and test one hypothesis at a time on a separate experimental branch. Disable or reject changes if Legacy or Low Latency regress. Preserve warm session state safely; do not force session cancellation on every caption or introduce unconditional hedges. Diagnose and repair export manifest membership of translation_modes.json separately after inspecting archive writer and reader contracts.

## Required release acceptance (not yet satisfied)
1. Full macOS GitHub CI including Swift/SQLite/transport/diagnostics tests, app/extension Release compilation, and IPA packaging.
2. Three comparable ≥5 minute on-device tests per mode using same source video, language, capture settings and balanced counterbalanced test order. Record cold/warm and fresh/reused caption groups separately.
3. Compare p50, p90, p95, P99 when sample count allows, measured OCR→PiP enqueue, actual model service time, displayed caption coverage, first-line retention, flicker, errors and battery/thermal.
4. Reject any candidate that has meaningful regression in Legacy or Low Latency; require Hybrid P95 < 1,409 ms and preferably < 600 ms before claiming improved Hybrid tail consistency.
5. Preserve persistent memory, provenance, schema, history, bundle identity and in-place installation; Temporary Memory must not durably store translations.
6. The v2.0.0 decision requires independent evidence supporting at least 90% confidence of faster real-device performance in **all three modes**, without quality or memory regressions. At present this gate is not met.
