## Completed implementation and fresh checks

Legacy preserves the verified default initializers and source-identical scheduling/confirmation/cache algorithms. Shared stop/session and diagnostic effects are explicitly disclosed in the architecture notes. New modes use strict source identity, one selection per confirmed revision, independent compatible memory lookup, bounded speculation, actual backend-slot ownership through cancellation, and source/session/language/revision rejection. Low Latency requests only explicit low latency, including retries, with recoverable unavailable status. Hybrid reuses speculation or recovers using a separate prepared low-latency lane, with bounded measured-policy inputs and no preview/refinement display.

One persisted selector replaces the overlapping switch. Migration reasons survive later sessions and unrelated settings remain intact. Active capture retains its selected system while a changed selection is pending. Low-latency results remain in a bounded strategy-specific session cache; they never enter preferred durable memory. Existing schemas, store identity, migrations and historical provenance remain intact; new known-default provenance is additive. Temporary mode keeps its existing zero durable translation-write guard.

Fresh CI passed pipeline regressions; controllable asynchronous coordinator/focus/identity tests; Legacy/source/schema/strategy contracts; comparison math/refusal tests; settings checks (107 keys, 15 routes); populated isolated 1.7.2 and 1.8.0 store reopen fixtures and failure recovery; UDP transport; diagnostic archive privacy/correlation/metric-origin checks; storage scaling smoke tests; Release compilation; metadata validation; and IPA upload. Local Python checks and `git diff --check` also passed. Synthetic timing inputs validate calculations, not device speed.

The final regression ensures matching speculation cannot beat an outstanding preferred-memory probe. Entirely cached selections stay in the memory cohort. Async SDK readiness is awaited outside Boolean autoclosures, then generation, preparation and exact session handles are revalidated before declaring readiness.
