# ScreenLingo 2.5.2 (build 120): Legacy finishes the caption it is translating, as built

Base: `claude/screenlingo-v2.5.1`. Work branch: `claude/screenlingo-v2.5.2`. Draft PR into the base branch. Contains everything in `docs/v2.5.1-specification.md`.

**Nothing was compiled or run in chat.** Swift was read and edited as text; all `scripts/test_*.py` were run. The GitHub Actions run is the first real test.
**No speed or quality improvement is claimed.** The effect is UNVERIFIED until Diagnostics on the same video shows it.

## 1. Evidence
- 2.5.0 report: `confirmed_continuity_loss` 31 to 341 per session; `confirmedSupersededAgeMs` P50 454 to 635 ms, which matches the handoff limit (`confirmedHandoffDelay`: 0.45 s, at most 0.9 s).
- Code: the Legacy drain runs one model call at a time. When caption B supersedes caption A, `cancelDrain` explicitly cancels only an early (speculative) session; A's confirmed call keeps running and the drain waits for it to unwind (`queueBehindConfirmedMs`, P90 55 to 253 ms, max 4661 ms). So B could not start earlier, and A's finished translation was thrown away.

## 2. Change
| Change | Switch | Default | Quality |
|---|---|---|---|
| While the active caption's own confirmed call runs (drain busy, owner confirmed, no other confirmed caption queued), a newer confirmed caption is held in the existing one-slot handoff for up to 1.0 s (`ConfirmedHandoffPolicy.maximumHold`). The active caption is shown when its call returns; the drain then replays the held caption at once. The 1.0 s cap keeps the replay inside the existing 1.2 s replay limit in `handleContent`. | Finish the caption being translated (new) | ON | Same text; captions that used to be dropped can be shown |

Not held: when another confirmed caption is still queued (the running call then belongs to an older caption), when an early call runs, in Low Latency.

## 2b. Changes from online research (2026-11-20)
| Change | Switch | Default | Source | Quality |
|---|---|---|---|---|
| Drop an OCR line when a wider line on the same row covers it and already contains its text (`Shared/OCRDuplicateFilter.swift`), in the normal and the quick read. Lines on other rows and different text are never dropped. | Drop duplicate OCR lines (new), both modes, CHANGES WHAT IS READ | ON | Apple developer forums thread 851862: on iOS 27 the `.accurate` reader returns whole-line duplicates ("the same text appears once as a combined line and again as individual strings"); the revision number did not change; `.fast` is unchanged. The test phone runs iOS 27.0.1, and "more than 4 lines" was the top extra-read reason in 2.5.0. | Removes doubled words; could drop a real repeated word only if it sits inside a wider line on the same row with the same text |
| Every Legacy live model call uses `translate(batch:)` (streaming); before, single-sentence captions used `translations(from:)`. | Streamed Legacy translation calls (new), Legacy only | ON | Apple documentation for `translations(from:)`: it "takes longer to return than `translate(batch:)`". | Same requests, same model, results mapped by client identifier as before |

Looked at and not used: the Swift-native `RecognizeTextRequest` (iOS 18) has the same recognition levels and a reported deadlock with more than two parallel requests (forums thread 784672); no speed advantage was documented. Image preprocessing for the iOS 27 accuracy regression: the report gives no steps.

## 2c. Existing switches turned on by default (owner request: turn on what should help)
| Switch | Was | Now | Why | Quality |
|---|---|---|---|---|
| Incremental translation recovery | off | on | Early calls are cancelled more often since 2.5.1; finished sentences of an interrupted call are kept for reuse. Never shows an unfinished caption. The default lives in `process` (allowed edit listed in `test_three_modes.py`). | none |
| Subtitle-area change detection | off | on | Looks at more of the subtitle area, so a new caption is noticed sooner. | none; may cost a few extra reads |
| Independent capture heartbeat | off | on | Keep-alive when frames are quiet; against a false "Capture stopped". Sends nothing while frames arrive. | none |
Saved values of these three are cleared once with the 2.5.1 ones (`LegacyV251Defaults.changedKeys`).
Left off on purpose: Fast OCR (lower accuracy), Multiple nearby text groups (may add wrong text), Confidence-aware OCR confirmation (turns off the pixel check's early-start signal), Direct PiP pixel-buffer rendering (rendering already about 1 ms), Continuous rotation recalibration (extra re-checks).

## 3. Risks
- If the active caption's call takes longer than 1.0 s (long captions, heat), the held caption is replayed at the deadline and supersedes the active one, as in 2.5.1.
- A caption shown for a very short time before the next one may look like a flicker. The switch turns it off.

## 4. Not changed in 2.5.1 or 2.5.2 (open)
- Long captions (161+ characters, about 1 to 1.4 s per model call): no change found that keeps the same quality without device data.
- Slowdown at Serious heat in very long sessions: early calls and the head start already stop at Serious; nothing else changed.
- The single 36 s confirmation in 2.5.0 session S6: the retained events do not show its cause.
