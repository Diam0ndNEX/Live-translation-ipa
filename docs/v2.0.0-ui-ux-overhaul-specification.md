# ScreenLingo v2.0.0 §12: UI/UX overhaul (full redesign)

Part of the 2.0.0 specification (`docs/v2.0.0-specification.md`), §12. Written 2026-11-07.
Branch `claude/screenlingo-v2.0.0`, draft PR #34 into `codex/screenlingo-v1.9.9-recovery-evidence`. Never `main`.
Version: **2.0.0 build 85** (2.0.0 is still undelivered; bump the build, keep 2.0.0, unless the user asks otherwise).

Nothing here is compiled or run. CI is the first real test. Every finding in §12.1 comes from **reading** code,
not from running the app. Nothing in this section is a speed claim; this work must not change translation behaviour.

## 12.0 What the user asked for

"The app needs a massive UI and UX overhaul. A lot of parts look bad, don't make sense, are buggy. Every part of the
app has a problem, some tabs don't work anymore. 2.0 should be the complete UI/UX redesign of every part. Add whatever
is needed. No limits: change the systems, change everything connected to the UI and UX, every aspect of the code may
be changed."

This is explicit authorization to rewrite every screen, the navigation, the theme, the view models, the settings
screens and their copy, and any system that only exists to serve the UI. It is **not** authorization to change the
translation pipeline (see §12.8). Decisions in this section are already made; the implementer builds them and does not
stop to ask about each one. The user can veto after seeing the PR.

### 12.0.1 Zero carry-over rule (binding)

The user asked for a **complete** overhaul. Therefore **none of the problems the current version has may appear in the
2.0.0 UI.** Concretely:

1. Every problem listed in §12.1 (U1-U10) must be gone in the new code. Not reduced, not moved, not restyled: gone.
2. Every additional problem the audit (§12.7 step 0) finds in any screen, including the files not yet read, is added to
   the list as U11, U12, ... and must be gone too.
3. Every problem the user reports later (for example which tabs do not work) is added the same way.
4. Old code that has the problem is **replaced, not wrapped**. A new screen must not embed, subclass or call a screen
   that still has a listed problem. Deleted code stays deleted (no dead copies of the old screens left in the target).
5. The PR must contain a **Problem → fix table**: one row per U-item with the file(s) and commit that remove it, and how
   it can be checked (source check, test, or device step). A U-item without a row, or with "partially", counts as
   **Not done** (§12.11).
6. A new source check (§12.10) fails the build if the known problem patterns return (for example `selectTab(`,
   `.preferredColorScheme(.dark)` forced, fixed font sizes, `Theme.` static colour reads, the old `Activity` tab).
7. What cannot be proven by reading or CI is marked **device check** in the table; the user verifies it (§12.12). Until
   then it is unverified, not fixed.

If fixing a problem would require touching the frozen translation code (§12.8), stop and report it instead of leaving the
problem in place silently.

## 12.1 What is wrong today (read in code, not reproduced)

Code read: `ScreenTranslatorApp.swift` (RootView), `HomeView.swift`, `UIParts.swift` (theme, reader, onboarding,
sharing), `WorkspaceViews.swift` (text/photo workspace, capture area editor, session controls), `LibraryViews.swift`
(Languages, Library), `SettingsCategories.swift` (Translation, History, Diagnostics settings), `project.yml`,
spec §0-§11.
Not read: `SettingsViews.swift`, `CustomizationViews.swift`, `ExperimentalFeaturesView.swift`, `MemoryManagementView.swift`,
`TestRunViews.swift`, the Diagnostics views in `Diagnostics.swift`, `PipelineSimulatorView.swift`, `Presets.swift` UI,
`PiPRenderer.swift`, `TranslationActivityView.swift`, `TranslatorEngine.swift`. The implementer must audit these first (§12.7).
Every U-item below is covered by §12.0.1: it must not exist in 2.0.0.

U1. **"Some tabs don't work": not found by reading.** No tab is obviously broken in the files above. Candidate causes
to check first: (a) `selectTab(Int)` uses hard-coded tab numbers (Home uses 1 and 3, Settings uses 3), so any reordering
silently opens the wrong tab; (b) every tab observes the whole `TranslatorEngine` (see U3); (c) screens in the unread files.
The user must say which tabs fail; until then this is unverified. In 2.0.0 every tab and every destination must work.
U2. **Navigation.** Five tabs: Live, Languages, Library, Activity, Settings. "Activity" is the developer diagnostics
dashboard in the main tab bar. Sheets (Reader, Session, Workspace, Capture area) each have their own Done button and
layout style. No deep links, no typed routes, no state restoration.
U3. **Whole-app redraws.** Screens use `@EnvironmentObject var engine: TranslatorEngine`, a 246 KB `ObservableObject`.
Any `@Published` change redraws every screen that reads `engine`, including Home during live translation. Likely
cause of jank and flicker; unmeasured.
U4. **Home is a 14-section scroll**: header, language card, live card, mode switch, Test card, activity card, output
tools, latency readout, readiness, tools, presets, quick settings, recent languages, status. The same information
appears several times (language-pack status three times; mode/content/speed pickers both on Home and in Settings).
There is no single obvious next action.
U5. **Theme.** `Theme.accent` and `Theme.gradient` read `UserDefaults` on every access and are not observable, so
colours can be stale until a parent re-renders. Three background tokens (`bg`, `background`, `surface`) are mixed.
Dark mode is forced (`.preferredColorScheme(.dark)`); no light mode, no high-contrast. Fixed font sizes (9, 13, 32,
64 pt) ignore Dynamic Type. Everything is a `.card()`, so hierarchy is flat. Portrait only.
U6. **Languages tab.** Tapping a row silently sets the *source* language; the *target* is only reachable by long
press. No pair concept, no per-language download progress, "Get" has no feedback.
U7. **Library.** Three toolbar controls plus Edit; "Delete visible unstarred entries" sits inside a filter menu next to
filters; export and restore are hidden in another menu; selection and "visible" semantics are easy to confuse.
U8. **Settings copy.** Pages are full of internal jargon ("speculation", "warm", "lanes", "strategy", "recovery") and
long footnotes; defaults and effects are hard to tell apart.
U9. **Capture area editor** draws a fake phone with two sliders; it does not show the real screen. **Reader**,
**Session** and **Workspace** are separate styles of the same idea.
U10. **Housekeeping.** Stale file headers ("v0.9.0", "v0.11.0"); two onboarding code paths for language choice;
duplicated language picker UI in four places (`LangMenu`, Languages tab, Workspace, Onboarding).

## 12.2 Goals

1. One clear primary action on every screen. Live: start/stop translation.
2. Progressive disclosure: basics first, advanced and developer tools behind clear doors.
3. Plain language. No internal pipeline terms in normal UI; precise terms only in Advanced and Diagnostics.
4. Consistent look from one design system with light, dark and accent support, Dynamic Type, VoiceOver, Reduce Motion.
5. Every screen has real empty, loading, error and success states.
6. No UI work on the broadcast/translation hot path. The UI may be slower than the pipeline, never the reverse.
7. Every existing feature stays reachable (see §12.9 parity list). Features are moved or renamed, not lost.
8. **No problem of the current version survives** (§12.0.1).

## 12.3 Information architecture

Tabs (four): **Live · Library · Languages · Settings**. Typed `AppTab` enum and one `AppRouter` (`ObservableObject`)
holding the selected tab, a `NavigationPath` per tab, and one `sheet` route. `selectTab(Int)` and its environment key are
removed; every call site uses `router.go(.languages)` or similar.

- **Live**: the capture screen (§12.4).
- **Library**: history and saved translations; Text & photos workspace entry.
- **Languages**: pair-first language manager.
- **Settings**: grouped, searchable. Contains **Tests & diagnostics** (live dashboard, Test Runs, ZIP export, pipeline
  simulator, memory management), reachable also from the Live Test card. The old "Activity" tab is removed as a tab.

Sheets use one shared `SheetScaffold` (title, Done/Close, detents, same background).

## 12.4 Design system (`App/DesignSystem/`)

- **Tokens**: color roles (`background`, `surface`, `surfaceRaised`, `separator`, `textPrimary/Secondary/Tertiary`,
  `accent`, `success`, `warning`, `danger`), spacing scale (4/8/12/16/24/32), radius scale (10/16/24), type scale built
  from Dynamic Type text styles only (no fixed sizes below 11 pt equivalent), motion durations.
- **Theme source**: one `@Observable`/`ObservableObject` `ThemeStore` injected at the root; accent choice stored under
  the existing `accent` key (no migration). Appearance picker: System (default) · Dark · Light. The forced dark scheme is
  removed; both schemes must be designed and checked.
- **Components**: `ScreenScaffold`, `SectionHeader`, `InfoCard` (replaces `.card()`), `StatusPill`, `PrimaryButton`,
  `SecondaryButton`, `IconButton` (44 pt minimum), `ListRow`, `LabeledToggleRow`, `Banner` (info/warning/error/success,
  with action), `EmptyState`, `ProgressRow`, `LanguagePairBar`, `LanguagePicker` (one implementation used everywhere),
  `SheetScaffold`, `ConfirmDestructive`.
- **Haptics and sounds**: one `Feedback` helper, respects the existing haptics setting.
- **Accessibility**: every control labelled; order sensible; no information by colour alone; minimum 44 pt targets;
  Reduce Motion replaces springs with fades; Increase Contrast supported; Bold Text and large text do not clip.
- Remove `UIParts.swift`'s theme code after migration; keep `BroadcastPicker`, `Sharer`, `ToastView`, `BrandMark`
  behaviour (moved, not rewritten, unless broken).

## 12.5 Screen specifications

### Live (replaces HomeView)
Three zones, top to bottom:
1. **Hero**: capture status (ready / connecting / live / paused / lost) with one big action: **Start** (system broadcast
   picker) or **Pause / Stop**. Shows the floating-window preview. One line of next-step help when idle.
2. **Language pair bar**: source ⇄ target with swap, pack status as a `StatusPill` (Ready offline / Needs download /
   Checking) that opens Languages. Recent pairs as a menu, not a row of chips.
3. **Controls strip** (always visible): translation system (Legacy · Hybrid · Low Latency) with the "applies when the
   broadcast stops" note; content type; reading speed. Everything else lives in a **More** sheet: capture area,
   window size, show original, auto-clear, presets, output tools (copy, freeze, retry, share), Focus reader, session
   controls, Text & photos.
- **Test card** (from §11) collapses to one compact row ("Test 1 · 2 of 3 modes saved") that opens the Test sheet
  (checklist, Save run, Clear test memory, Export report, Test Runs list).
- Latency readout and troubleshooting move to a **Status** sheet (opened from the hero status), not the main scroll.
- Home screen no longer scrolls on a standard iPhone in the idle or live state.

### Languages
Pair-first: top card shows the current pair with swap and status; below, one searchable list. Tap a row opens a small
action sheet (**Translate from** · **Translate into** · **Download**). Per-row download progress and
clear states (ready, downloading, needs download, unsupported). Remove the silent set-source-on-tap behaviour.

### Library
One toolbar button for Select, one for Filter (All · Saved · Last 7 days), one **More** (Export text / CSV / JSON,
Restore backup). Destructive actions only in Select mode or swipe, always with confirmation and Undo. Rows: translation
first, original second, metadata third. Detail view: large text, copy / listen / share / save, note, share card.
Empty state explains private sessions. Entry button for **Text & photos**.

### Settings
Grouped, searchable, with a **Basic** and **Advanced** split per page. All copy rewritten in plain language: what it
does, what changes if you turn it on. Jargon only inside Advanced, each with a one-line plain explanation. Every page
keeps a **Reset this page** action. **Tests & diagnostics** section as in §12.3. Settings search finds every setting
by plain-language words.

### Focus reader, Session, Text & photos, Capture area
- **Reader**: keep features; one controls sheet instead of a bottom bar toggle; large-text friendly.
- **Session** merges into the Status sheet (§Live).
- **Text & photos**: one flow: input (type / paste / photo / file) → Translate → result with copy / listen / share; same
  `LanguagePicker`; progress and error states.
- **Capture area**: show the **last captured frame** (or a placeholder) with a draggable, resizable box for the area;
  presets Full screen / Subtitles / Middle. Verify what frame data the app process can obtain before building this (the
  broadcast extension owns capture); if none is available, keep the diagram but make it honest, label it "Preview", and
  say so in the PR. (Because of §12.0.1, this case must be reported in the PR as a U9 item that is only partly fixable,
  and the user decides.)

### Onboarding
Short guided setup that actually checks things: 1) pick languages and download the pack (with progress), 2) start a
test broadcast, 3) confirm the floating window opened, with a visible success state and a Skip that can be resumed from
Live ("Finish setup" banner). One language-picker path only.

### Other screens (audit and redesign in the same system)
Memory management, Test Runs (§11 views), Diagnostics dashboard, Experimental features, Pipeline simulator, Presets
editor, Customization, Backup & restore. Each gets the new scaffold, plain-language copy and states. Developer-heavy
screens may stay dense, but must use the design system and live under Tests & diagnostics / Advanced.

## 12.6 Systems changes (allowed and required)

- **Router** (§12.3) replaces `selectTab`.
- **Narrow observation**: stop passing the whole engine to leaf views. Introduce small view models or
  `EquatableView` wrappers fed by narrow publishers (capture status, language pair, caption text, test-run state), so a
  caption update redraws only the preview, not the whole screen. Do not change `@Published` semantics inside
  `TranslatorEngine` hot paths; add read-only derived publishers or snapshot structs outside them.
- **Settings access**: group related `@AppStorage` keys behind small typed structs per screen. **Keys and defaults stay
  unchanged.** No migration. `scripts/test_experimental_settings.py` and the "one writable owner per setting" check must
  keep passing; update them only when a key moves, with the reason in the commit.
- **Copy**: one `Strings.swift` (or string catalog) for user-facing text, so wording is consistent and reviewable.
- **Feedback**: one toast/banner system (queue, severity, action) replacing ad-hoc `engine.toast` calls in views.
- **Error surfaces**: every `engine.status` / `downloadMessage` style string shown in UI becomes a typed state with a
  readable message and a next action.
- **Orientation**: keep portrait for the app unless landscape is verified for Reader and Text & photos; if enabled,
  these two only, with the capture extension untouched.

## 12.8 Hard boundaries

- Do not edit the bodies of the frozen functions in `SampleHandler`, `TranslatorEngine` (`process`, `drain`,
  `cachedCaption`, `extractTexts`, `selectBlocks`) or `TranslationSystem`, or `ModeTranslationService` scheduling.
  UI code only calls existing engine methods. If a UI need requires an engine change, add a new method or derived
  snapshot outside the frozen code and say so in the commit.
- No new work on the main thread inside the broadcast/translation path. No new SQLite operations in the capture path.
- Settings keys, defaults and stored data formats stay as they are (history, memory, test runs, presets, backups).
  Backup/restore must still read backups made by build 84.
- Privacy stays metadata-only for diagnostics; no text in exports by default.
- No speed claim from this work. Translation latency must not regress beyond noise in any mode; the UI must not add
  redraws during live translation (§12.6).
- Everything is on `claude/screenlingo-v2.0.0`; draft PR #34 stays draft; never `main`.

## 12.10 Tests

CI does not run a simulator for UI (earlier PRs note simulator previews are skipped by workflow policy), so UI tests are
logic and source tests:
- `Tests/Navigation/main.swift`: `AppRouter` routes, tab mapping, sheet routing, no `selectTab` left (source check).
- **Carry-over guard** (`scripts/test_ui_no_carryover.py`, wired into CI): fails if any known problem pattern returns:
  `selectTab(`; forced `.preferredColorScheme(.dark)`; fixed `.font(.system(size:` below 11 pt outside `BrandMark`;
  static `Theme.accent` / `Theme.gradient` reads; the five-tab `TabView` with an Activity tab; `.card()` still in use;
  more than one `LanguagePicker` implementation; file headers older than 2.0.0 in UI files; any U-item pattern the audit
  adds. Each pattern in the script carries its U-number.
- Source checks: every Settings key in the parity list still has one owner.
- View-model tests for the narrow publishers (pair status, capture state, test card state).
- Existing tests keep passing; update only for moved symbols, with the reason in the commit.
