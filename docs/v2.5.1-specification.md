# ScreenLingo 2.5.1 (build 119): Legacy speed and a self-healing capture link, as built

Base: `claude/screenlingo-v2.5.0`. Work branch: `claude/screenlingo-v2.5.1`. Draft PR into the base branch.
Input: the 2.5.0 (build 118) report of 2026-11-20 (6 Legacy sessions, pt>en, movie preset) and the owner's request: concentrate on Legacy, lower its latency as far as possible without lowering quality, bring speculative (early) translation back, fix translation stopping until the app is restarted.

**Nothing was compiled or run in chat.** Swift was read and edited as text; all `scripts/test_*.py` were run. The GitHub Actions run (`checks` and `build`) is the first real test.
**No speed improvement is claimed.** The 2.5.0 report had only Legacy runs, on six different videos (0-1% shared captions), so it gives no before/after or mode comparison. Every effect below is UNVERIFIED until Diagnostics on the same video shows it.

## 2. What changed
| # | Change | Switch | Default | Quality |
|---|---|---|---|---|
| 1 | App link: a peer that fails, is cancelled or ends its receive loop is dropped, so the next datagram opens a new connection; after 5 s of capture silence (`heartbeat_timeout`) the listener is restarted (`LoopbackServer.restart`). | none | always | none |
| 2 | Extension link: a failed connection, or 5 failed sends in a row, opens a new one (at most one attempt every 2 s); listening for settings restarts on it. `SampleHandler+Reconnect.swift`. | none | always | none |
| 3 | Every first reading starts its early translation again (2.3.9 behaviour). | Wait for confirmation before early Apple Default work | OFF (was ON) | none: early results are used only when the confirmed text has the same units |
| 4 | Eager early translation: a first reading that arrives while the previous confirmed caption is being translated or waits to be shown is not dropped; it is admitted with the same rules (confidence, adaptive window, deferral switch) and queued behind the running confirmed job. Only the newest is kept, only when no confirmed caption is queued; the drain always takes confirmed work first. It never replaces the active caption. `TranslatorEngine+EagerSpeculation.swift`, `EagerSpeculationPolicy`. | Eager early translation (new) | ON | none |
| 5 | A confirmed caption no longer waits for a different early call to stop. | Legacy confirmed own lane | ON (was OFF) | none; two Apple Default calls may run at once and slow each other |
| 6 | Saved values of switches 3 and 5 are cleared once (`LegacyV251Defaults`), so the new defaults reach people who toggled them before. The toggles work normally afterwards. | none | once | none |
| 7 | Head start: matched by words in order (`HeadStartText`; letters, accents and punctuation must still be identical), the quick read uses the normal read's language correction, and it also runs when the phone is Fair (still held at Serious, Critical, Low Power Mode, cooling settings). The governor (80% of the last 12 right, at least 6) is unchanged. | Legacy head start | ON | none: the normal read still decides what is shown |
| 8 | Pixel check fingerprints up to 8 lines (was 4). The ink tolerance is capped at 6 points (`maximumAllowance`), so longer captions are not checked more loosely; up to about 4 lines nothing changes. Ink contrast, tolerance, minimum ink and dwell are unchanged. | Pixel-verified confirmation (existing) | as before | same evidence per line |

Not changed: OCR settings of the normal read, confidence gates, confirmation reads and dwell, the Legacy drain, `process`, `cachedCaption`, `extractTexts`, `selectBlocks`, the model and its strategy, memory, Low Latency.

## 4. Risks
- More early calls (3, 4, 7) mean more Apple Default work and heat. Early calls already stop at Serious/Critical and in Low Power Mode.
- Own lane (5) can run two Apple Default calls at once; never measured.
- Item 4 changes the order of work in the single Legacy drain. Confirmed work still goes first; a wrong early call is cancelled or detached as before.
- The extension reconnect takes the OCR lock for a moment; frames that arrive then are skipped, as when OCR is busy.
