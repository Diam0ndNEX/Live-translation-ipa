# ScreenLingo 2.6.2 (build 127): automatic comparison between sessions, faster CI, as built

Base: `claude/screenlingo-v2.6.1`. Work branch: `claude/screenlingo-v2.6.2`. Draft PR into the base branch.
**Nothing was compiled or run in chat** (no Swift compiler). All `scripts/test_*.py` were run. The GitHub Actions run is the first real test.
**Every effect is UNVERIFIED.** 2.6.1 had not built when this was written; two CI errors were found and fixed on that branch (missing commas in the changelog, a duplicate test variable).

## 1. Automatic comparison (`DiagnosticArchive+Regression.swift`)
In the report's section 0, every session is compared with the one before it (oldest first). Only sessions that the existing comparison rules call comparable are judged (same device, OS, measurement boundary and behaviour switches). Otherwise the line says why it was not compared.
Flags: P95 of enqueue latency, OCR, confirmation and the two model times up by 10% and 20 ms or more (at least 20 samples each); more stalls or lane resets; a guard that tripped; flagged captions per caption up by 2 points. A fall of the same size is listed as "better". Limits are fixed and were not tuned on device data. Nothing is marked by hand.

## 2. CI
- The build workflow runs once per push (the pull_request trigger duplicated every run on macOS).
- The Python contract checks run in a Linux job (`python-checks`); the Swift programs, the SQLite and transport checks stay in the macOS `checks` job; `build` is unchanged and runs in parallel.
- UI screenshots are manual only (Actions tab, "Run workflow").
- Homebrew auto-update and cleanup are off for the XcodeGen install.
A passing run took about 4 minutes per job in the 2.5.6 run; the long waits came from queued macOS runners and duplicate runs.

## 3. Tests
`Tests/DiagnosticArchive/main.swift` (slower session with a stall is flagged, faster is "better", +5% is not flagged, another device is not compared, the report names the regression); `scripts/test_three_modes.py` 2.6.2 contracts; version asserts 2.6.2/127.

## 4. NOT built
Per-caption record with worst-N retention; first-OCR wait measurement; guards for other switches; quarantine of flagged reused units; memory staleness identity (OS build); cache warm-up; read-only memory screen; content profile; progressive display; thermal curve; adaptive capture cadence; pixel self-calibration; fuller CI replay; idle shadow check. Run segmentation across capture stop and start already exists (`resumeRun` keeps one run). Reason: these touch hot paths, schemas or recorder internals that cannot be checked without a compiler, and 2.6.1 has not yet built.
