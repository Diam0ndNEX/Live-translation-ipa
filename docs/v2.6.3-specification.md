# ScreenLingo 2.6.3 (build 128): memory warm-up and quarantine, slowest captions, as built

Base: `claude/screenlingo-v2.6.2`. Work branch: `claude/screenlingo-v2.6.3`. Draft PR into the base branch.
**Nothing was compiled or run in chat** (no Swift compiler). All `scripts/test_*.py` were run; CI compiles the app and runs the Swift test programs. **Every effect is UNVERIFIED** until a device report exists.

## 1. Memory care (switch `memoryCare`, default ON, report arm `memoryCareAB`)
- **Warm-up** (`TranslatorEngine+MemoryCare.swift`, `TranslationMemoryStore+Care.swift`): when memory opens, up to 400 (at most a quarter of the RAM capacity) of the most recently used ready, persisted units of the current rules and target language are loaded into RAM. A unit saved with two translations is left out. Warmed units are marked as saved (never written again) and have the lowest use mark, so they are trimmed first. Counter `memoryWarmed`. Expected effect: the first sighting of a repeated sentence needs no disk lookup (unverified).
- **Quarantine**: when a shown caption has a lost number, a word repeated three times, or the source returned unchanged, every unit reused from memory in that caption (touched in the last 64 RAM uses, its translation inside the caption) is checked on its own. One with the same defect is removed from RAM, complete captions containing it are dropped, and its saved row (and the rows a loose lookup would reuse for it) is set back to validation. The text stays saved. At most once per unit per app run. "Unchanged" counts only for a unit of three or more words (names may stay). Counter `memoryQuarantined`, finding `memory_quarantined`.
- No schema change. A database error gives an empty result.

## 2. Slowest captions (`DiagnosticArchive+SlowCaptions.swift`, `Diagnostics+SlowCaptions.swift`)
The 8 slowest captions of a run are kept with their stage times (OCR, confirmation, delivery, queue, translation, display hold, rendering) as counters `slow<rank>_<stage>` (numbers only). The report shows a table with the longest stage marked. Finding `slow_captions_mostly_<stage>` when at least 5 kept captions of 1200 ms or more mostly share one longest stage (60%).
