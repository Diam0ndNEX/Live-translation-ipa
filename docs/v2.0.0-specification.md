# ScreenLingo v2.0.0 (build 83): review and plan

## What this release changes

- Version 2.0.0, build 83 (`Shared/Shared.swift`, `project.yml`, and the two CI contract scripts that assert the version).
- CI now also builds `claude/**` branches, and pull requests into `codex/screenlingo-v1.9.9-recovery-evidence`.
- **No runtime behavior changes.** Capture, OCR, the three translation systems, memory and PiP are identical to v1.9.9 / build 82.

The runtime was left alone on purpose. This code base protects its hot paths with source-level contract tests
(`test_v199_performance.py`, `test_three_modes.py`, `test_thermal_parity.py`, and others) that compare whole
functions against an older commit, and the changes below could not be built, run or profiled in the environment this
release was prepared in. Each item is a lead to verify with the Diagnostics export on a device, not a measured fix.

## Scope of the review

Read in full: `BroadcastExtension/SampleHandler.swift`, `App/PiPRenderer.swift`, `App/LoopbackServer.swift`,
`Shared/Shared.swift`, `project.yml`, `.github/workflows/build.yml`, and the CI contract scripts.

**Not read:** `App/TranslatorEngine.swift` (about 240 KB), `App/Diagnostics.swift`, `Shared/TranslationSystem.swift`,
`App/ModeTranslationService.swift`, `App/TranslationMemoryStore.swift`. Per-mode findings for Legacy, Hybrid Recovery
and Low Latency therefore need a follow-up pass over those files.

## Findings, ranked by expected value and safety

### 1. Loopback datagram size (verify first, potential correctness bug)

`SampleHandler.send` only trims a packet when it exceeds 60,000 bytes, and `LoopbackServer` accepts up to 60,000 bytes.
Both sides use UDP. On Darwin, `net.inet.udp.maxdgram` defaults to 9,216 bytes, and `NWConnection` reports larger
datagrams as an error. The send completion handler ignores errors.

A packet carries about 35 metadata fields (roughly 1 KB) plus each `OCRLine` as JSON (about 150 bytes with full-precision
doubles and the text). Around 55 or more lines in one read could exceed 9 KB and be dropped silently. That would need a
very text-dense capture area (manga page, game log), so the impact is limited, but the failure would be invisible.

Suggested checks and fix:
- Add a transport test that sends a 60-line `Packet` through `LoopbackServer` on macOS and on device.
- If it fails: encode, and while the data is larger than about 8,000 bytes, drop trailing lines and re-encode; surface the
  completion error in diagnostics (`send` failure counter).
- Round `OCRLine` doubles to 4 decimals to shrink every packet by roughly a third.

### 2. PiP frame preparation

The default path draws a `UIImage` with `UIGraphicsImageRenderer`, then copies it into a pooled `CVPixelBuffer` with
`CGContext.draw`. The `directPiPBuffer` experiment (already implemented, default off) draws straight into the pooled
buffer and removes that copy. Compare `PiPFrame` signpost intervals with the toggle off and on on a device; if it
wins without visual differences, make it the default (this requires updating the default assertion in
`scripts/test_experimental_settings.py`).

Smaller items in the same file:
- `PiPStyle.make` reads about ten `UserDefaults` keys each time a style is built; cache them and invalidate on change.
- `PiPStyle.visuallyEquals` compares `String(describing: design)`; compare the underlying value instead.

### 3. Capture extension per-frame work

- The "pressure" condition (`confirmationBurst`, `pressure`, `smartCool`, Low Power Mode, thermal state) is written twice
  and evaluated twice for every ReplayKit frame, including frames that are then skipped. Compute it once per frame
  (or cache thermal state from `ProcessInfo.thermalStateDidChangeNotification`). Keep the literal
  `ThermalPerformancePolicy.automaticPressure(for: ProcessInfo.processInfo.thermalState)` expression that
  `test_thermal_parity.py` looks for.
- `JSONEncoder()` and `JSONDecoder()` are created for every packet and config message (`SampleHandler`, `LoopbackServer`).
  Hold one per queue.
- `os_proc_available_memory()` is called up to three times per OCR pass and once per send; read it once per pass.
- OCR is always `.accurate`, which protects confirmation quality. Leave as is unless diagnostics show OCR time dominating.

### 4. Loopback server

- `send(_ config:)` encodes on the caller's (main) thread; move encoding into the server queue.
- The transport test covers only tiny ping packets (see finding 1).

### 5. CI and release hygiene

- The push trigger is an explicit, growing list of 30+ branches. `codex/**` plus `claude/**` would remove the need to
  edit the workflow for every release. (`claude/**` is added in this release.)
- `pull_request.branches` did not include the current line; the v1.9.9 branch is added in this release.
- The version is asserted in four places (`Shared.swift`, `project.yml` three times, and two scripts). A single source
  (for example, read `MARKETING_VERSION` from `project.yml` in the scripts) would make each bump a one-file change.
- `brew install xcodegen` runs on every build; cache it, and run the independent `swiftc` test binaries in parallel jobs
  to bring the 20-minute budget down.
- `README.md` still opens with the v1.9.3 section; newer releases are only in `AppVersion.changelog`.

### 6. Per-mode performance (Legacy, Hybrid Recovery, Low Latency)

Not assessed (see Scope). The project's own acceptance rule is the right one: run the same content through all three
systems with the Diagnostics export (`scripts/compare_three_modes.py`) and compare first-OCR-sighting to PiP-enqueue
percentiles. Share those exports and the next pass can target the slowest stage in each mode.
