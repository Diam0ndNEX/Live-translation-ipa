## CI speed (workflow files handed over by hand)
Measured on the last green run before this change (9m 14s, one job): Build 229 s, SQLite memory migration 111 s, storage benchmark 60 s, about 25 other steps at roughly 10 s each.
- `build.yml` is split into two jobs that run in parallel: `checks` (all contract tests, Swift test builds, memory migration, diagnostics, Test Runs) and `build` (icon, xcodegen, xcodebuild, metadata check, IPA). The `build` job uses a shallow checkout.
- The "Storage scaling smoke benchmark" step is removed from `build.yml`. The manual `memory-benchmark.yml` workflow runs the same script at larger sizes.
- `ui-screenshots.yml` no longer starts on every push that touches `App/` or `Shared/`; it starts on `App/UI/**` changes, on its own files, or by hand.
- Expected effect: wall time close to the longer of the two jobs instead of their sum, about 5 minutes. UNVERIFIED until a run on the new files is timed.
- Side effect: the IPA is built and uploaded even when a check in the `checks` job fails. A red `checks` job still marks the run as failed.
- All Python tests pass locally against the new workflow files. Nothing was compiled or run in chat.
