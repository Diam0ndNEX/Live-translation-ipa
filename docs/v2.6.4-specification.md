# ScreenLingo 2.6.4 (build 129): steady display, report fixes, as built

Base: `claude/screenlingo-v2.6.3`. Work branch: `claude/screenlingo-v2.6.4`. Draft PR into the base branch.
Built from the first 2.6.3 device report (build 128, 19 min, Legacy, pt>en, iPhone18,2). **Nothing was compiled or run in chat**; CI compiles and runs the Swift tests. Effects are unverified until the next report.

## 1. What the 2.6.3 report showed
- Speed: n 502, P50 499 ms, P95 1160 ms. All 8 slowest captions were slow in the Apple translation call (1.0 to 2.7 s, long texts), not in OCR, queue or display.
- Stalls: 2 calls hung and were abandoned at the 6 s limit; translation went on without a lane reset. This is the 2.6.0 watchdog working; earlier builds would have stopped.
- Guard: the growing-subtitle wait was turned off twice (60% of held readings dropped), as designed.
- Display flicker: one subtitle was shown four times in one second because OCR alternated between "Irmã" and "Irmă"; a subtitle and a logo ("Goá aiky") were shown in turn.
- The "RAM at start 400 ⚠️" warning came from the 2.6.3 warm-up, not from test memory. The low memory hit rate finding still said miss reasons were not recorded.
- Calls that started while another session's call was running were slower (P50 644 vs 363 ms, 52 of 334). Not changed here: an Apple call cannot be stopped early, so the lever needs more data.

## 2. Steady display (switch `stableDisplay`, default ON, report arm `stableDisplayAB`)
`DisplayStability` (`Shared/TranslationSystem+V264.swift`, pure). Before a new caption is drawn (not for typed text, not when the source is unchanged):
- **Another reading**: letters and numbers equal after removing accents, case and width → the shown caption stays (up to 6 s after it appeared).
- **Flip back**: the new caption was shown in the last 8 s and the current one has been visible less than 2 s → the current one stays.
Held like an identical frame: nothing is drawn, the caption stays current. New text is always shown at once. Counters `displayHeldVariant`, `displayHeldFlip`, finding `display_flicker_held`. A cleared screen resets it.

## 3. Report fixes
- Preloaded units are counted per app run (`memoryWarmed` no longer resets at run start); RAM at start shows "(preloaded)" and warns only when it holds more than was preloaded.
- The low-hit-rate finding points to the miss table.

A change to calls that overlap another session's call; logo/watermark detection; the items listed in the 2.6.3 spec section 4.
