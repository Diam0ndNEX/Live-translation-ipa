# ScreenLingo v1.5.0 — Experimental Features tab

## Navigation

Settings → **Experimental Features** (one discoverable page, searchable as “Smart pipeline,” “low latency,” “lyrics,” and “experimental”).

The previous Smart pipeline navigation entry is now replaced with Experimental Features. A compatibility wrapper remains for any older internal route. Normal OCR, translation speed, power, language, PiP, and storage controls remain where they were.

## Saved settings

No settings keys have been renamed or erased, no defaults changed, and no translation-memory or history migration occurs simply from opening the page. Values already enabled (such as subtitle tracking, adaptive OCR, smart cool, and predictive warm-up) remain enabled. The five v1.5.0 trials remain disabled until selected. A page-level Reset to defaults resets the underlying keys to their existing defaults, which is distinct from turning all features off.

## Grouped controls

- **New model experiments:** low-latency model strategy (iOS 26.4+), incremental speculative batch recovery, predictive warm-up (existing).
- **New OCR and lyrics experiments:** subtitle-area detection (requires Skip unchanged frames), nearby lyric group retention (Movie mode).
- **New rendering experiment:** direct PiP pixel-buffer rendering.
- **Existing recognition:** adaptive OCR detail in Balanced, confidence-aware confirmation, confirmation deadline.
- **Existing subtitle continuity:** spatial/lifetime tracking, duplicate copies, stable transitions, protected short handoffs.
- **Existing translation intelligence:** selective pre-translation, minimum speculative confidence, adaptive speculation, contextual source language, automatic-language failure recovery.
- **Existing device/rotation options:** continuous rotation calibration, Smart Cool controller.
- **Controlled comparison:** fresh translation test without reuse.
- **Built-in (informational):** privacy-safe profiling markers and PiP heartbeat backpressure. These are automatic behaviors rather than fake toggles.

Each option has a short explanation of what it is intended to do and any important quality/speed/capture limitations.

## Behavior/invariants

- Low-latency strategy changes invalidate the old model session but preserve the original default model cache-rule digest when the option is off. The control is disabled on older iOS versions.
- Settings affecting the pipeline call `pipelineSettingsChanged` to invalidate pending candidates safely; model strategy uses `translationStrategyChanged`; PiP direct render changes rerender via `applyStyle`.
- Each option is bound once with `@AppStorage`. No duplicate switch is left in Reading & OCR, Performance & power, or the former Smart pipeline page.
- Dependency controls disable relevant experiments when prerequisites are absent without silently changing saved user values.
- Existing custom presets and bulk backup/reset continue to use the original keys.
- CI runs `python3 scripts/test_experimental_settings.py`, followed by the normal iOS Release/IPA gates. The script guards routing, duplicate controls, defaults and change callbacks.
- Device acceptance needs a settings navigation and round-trip test, each toggle enabled/disabled in a capture session, and restart/backup/preset persistence. Test this alongside `docs/v1.5.0-optimization-research.md` and `docs/v1.5.0-acceptance.md`.

The UI consolidation itself does not constitute proof that the experimental processing strategies improve translation speed or coverage.
