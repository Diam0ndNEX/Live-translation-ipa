# ScreenLingo v1.4.3 — high-throughput, resource-aware legacy validation

## Diagnosis of v1.4.2 slowness
`tickCount % 60 == 0` plus `lastIdleValidationAttempt > 90` and `maxEntries: 1` restricted automatic processing to about one record every 120 seconds. Manual validation processed at most five sequential model calls. A 277-record backlog could thus require over nine hours of eligible automatic idle time.

## v1.4.3 behavior
- Default user-opt-in remains disabled. No validation occurs in a private session, when PiP or capture is running, or when the app is backgrounded.
- **Automatic:** up to 24 eligible historical sentences per sweep, with an 8-second cooldown *after the previous batch finishes* under nominal thermal conditions.
- **Manual button:** up to 48 entries in one sweep; hard ceiling 50.
- **Bounded concurrency:** at most two independent iOS 26 TranslationSession model workers. Each handles a batch of at most 12 texts via a single `translations(from:)` call. When thermal state becomes Fair the next batch uses one worker and a 20-second cooldown. Serious/Critical thermal or Low Power Mode stops scheduling and prevents database commit.
- **Safety:** before scheduling and immediately before SQLite writes, require unchanged language, rules digest, app foreground, available memory, no in-flight memory writes, no capture and no PiP. Starting capture cancels the validation task. Background/system interruption can suspend or end work without losing earlier committed batches.
- **SQLite throughput:** select historical rows in indexed pages rather than one fetch per entry; store an independently translated result as the only authoritative current v4 memory, preserve original legacy outputs/provenance, and classify the entire batch in one transaction. Duplicate, stale, malformed or storage-full cases roll back the whole batch.
- **Progress:** show concurrent worker count, batch selected/validated/skipped and session verified total in Translation Memory. Skipped entries (unsupported source, unsuitable OCR cleanup, incompatible segmentation) remain preserved, not silently marked validated.
- **Cursor:** automatic sweeps advance across skipped historical rows and stop after exhausting eligible records in the current session; explicit manual validation can rescan after language packs/settings change.

## Tests and release gates
1. Pure batching: 48 inputs across language pairs, ordered source grouping, 12-item model-call ceiling, concurrent worker cap, thermal cooldown.
2. SQLite: 30 imported historical rows paginated in groups of 24 and 6; atomic commit of fresh v4 output; mismatched language or duplicate IDs rejected; second-insert SQLITE_FULL fault preserves all old entries and previously committed memory.
3. CI: pipeline regressions, SQLite migrations, diagnostic privacy, storage scaling, iOS Release build, metadata 1.4.3/47 and IPA.
4. On device: measure entries/minute, responsiveness when resuming ReplayKit, battery/thermal state, low-storage interruption, upgrade persistence. Automatic iOS scheduling/model throughput is not guaranteed. Do not claim a 24x or 50x measured speedup without real-device timings.

No text is uploaded and no bulk validation is permitted while translating a live video.
