# ScreenLingo 1.4.7 (51)

Based on verified 1.4.6 head 86aa5cf54a9a122f5e1b461dbbf7f158813b5862.

## Selective legacy deletion

Memory settings exposes Delete unvalidated legacy entries with an explicit
confirmation describing all languages and all lengths. The store executes only
`DELETE ... WHERE validation_state='needs_validation' AND rules_version IS NULL`
inside one transaction. The predicate is re-evaluated at execution, preserving
validated_legacy, superseded_legacy, ready v4 and quarantined current-rule rows.
Foreign-key cleanup applies only to metadata associated with deleted rows.
Migration receipts remain, preventing automatic reimport from retained originals.
Recovery copies are retained and may contain these rows; an intentional restore
or import is separate from automatic migration. No background deletion exists.

Engine deletion requires no capture, PiP, translation, warmup, validation task or
pending writes and uses the mutation barrier and revision discipline. UI success
uses the COMMITTED row count. Search refresh failure cannot misreport a committed
delete as a failed delete. Valid cached translations, history and settings remain.

## Speculative-work intelligence

After 32 completed runtime observations, at least 80% discarded pipelines and
less than 5% reused pipelines, speculative opportunities back off to one in four.
The existing moderate mode retains alternate probes. The rolling window can
recover and confirmed processing never enters this gate. Speculation preference,
confidence, thermal and power checks remain. This may reduce successful early
translations too: compare latency and actual model workload before acceptance.

Diagnostics now distinguish app preemption requests from actual engine cancelled
calls, count confirmations matching active speculative text, attach opaque
candidate IDs to model submission/category completion events, and separate
bounded completed confirmed/speculative model-time distributions. A completed
call may still be discarded by freshness checks; completion does not imply reuse.

## Legacy validation diagnostics

session.json includes fixed-name numeric inventory and last-batch exclusion
counts, plus the scan's source/target codes. These are LAST-SCAN snapshots, not
cumulative work counters, and do not belong in interval delta sums. Counts may
be stale after deletion or a settings change; absent means no captured snapshot
in this diagnostic session. No source/translated text, keys, paths or UI messages
are exported. Scan counts still distinguish potential candidates from eligibility.
