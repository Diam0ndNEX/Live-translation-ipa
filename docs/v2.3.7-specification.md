`TranslatorEngine.swift` is still large on purpose: stored properties, `init` and every member that a contract test matches by its text (the hot path, for example `process`, `drain`, `handleModeCaption`, `noteModeEvent`) stay in the main file, and so does everything that calls those private members.

## How the split was done
- A script moved whole members (functions, computed properties, nested types) into `extension Type { }` files named `Type+Topic.swift`. Stored properties, `init`, `body` and members with `override` stay in the main file.
- Moved text is identical. A line multiset check against the previous commit shows only `private` removals and file wrappers (access-only changes: engine 157, recorder 92, dashboard 45, archive 2, settings 0).
- A member lost `private` only when its name appears in another file of the same type. Declarations that tests match by `private` text were kept private, and anything that mentions them stayed with them.
- One type had to lose `private` as well, because an internal method returns it (`CostToken`). A signature check found it.

## Test changes (meaning unchanged)
- `test_three_modes.py` `function()` accepts a function that is no longer private and ends at the function own closing brace (neighbouring members may now live in other files).
- `test_ui_no_carryover.py` toastText lint and `test_ui_layout_rules.py` R6/R10 also cover the `TranslatorEngine+` and `DiagnosticsDashboard+` files.
- `test_mode_diagnostics_ui.py` looks for `struct DiagnosticsBody: View` (now internal).
- `test_thermal_parity.py`, `test_v199_performance.py` and `test_v221_contracts.py` read the recorder and dashboard through `read_source`.
