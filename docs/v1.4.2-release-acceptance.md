# ScreenLingo v1.4.2 — Release candidate and acceptance matrix

## Changes
- **Memory 2.1 lazy legacy verification.** Existing v2/v3 entries with incomplete rule provenance remain inaccessible to automatic lookup. A fresh confirmed result under a current v4 rules digest can classify an *exactly matching* historical source/language/target/context record as `validated_legacy` when the translation agrees, or `superseded_legacy` when it differs. The new current-rule entry is the one used in live playback. No legacy key is directly promoted to `ready`; no user history, original output, provenance, or database recovery backup is deleted. Unparseable or context-incompatible entries stay `needs_validation`, potentially indefinitely.
- The fresh proof is only set on **display-eligible newly computed model results**. RAM, persistent SQLite, speculative results, imported backups, and the opt-in Fresh translation test cannot silently validate historical entries. The model was already required for the live subtitle; validation does not launch extra translations.
- The current-row commit and old-row status update are one SQLite transaction. Failed saves keep the pending data and proof for bounded retry. User quarantined v4 records are excluded from automatic legacy reconciliation.
- Memory screen displays total ready, old waiting, old independently verified and old superseded counts. The metadata-only diagnostic ZIP also captures final totals and validation/supersession deltas over 15-second windows.
- **Subtitle continuity:** protect currently translating confirmed text when a later near-equivalent OCR candidate would otherwise cancel it before the duplicate check. Truly changed dialogue or one altered lyric line still proceeds normally.
- **Model warm-up:** do not warm an already-ready language pair twice; do not treat a failed warmup as reusable. Existing thermal and Low Power Mode guards remain active.

## Measurements from the prior reports motivating this release
- v1.4.0 showed 277 historical entries consistently needing validation across three sessions even as ready entries grew.
- v1.4.1 (new five-minute Portuguese video) felt more responsive, but OCR→PiP enqueue p95 remained about 1.78 s; early model batches were slower and six confirmed candidates were superseded before presentation.
- This is **not** evidence that all six captions were missed or that late-screen presentation timing is known. Different videos are confounded by text visibility, caption density and memory/cache state.

## Signed-iPhone acceptance (not yet verified by CI)

- Perform a five-minute movie capture with metadata-only detailed diagnostics and the same settings as previous tests. Inspect startup warm-up events, confirmation churn, OCR pass intervals, memory classification and p95.
- Replay the old problematic video on the same build. Do not conclude an algorithmic speedup solely from a different five-minute video.
- Record thermal state/comfort and confirm no recurring model warm-up during otherwise idle periods when an installed direct session is already ready.
- Check captions with static overlays and changing lyric rows. Full translation correctness can only be assessed against user-observed video frames, not diagnostic metadata alone.
- Check memory match updates remain background and do not block OCR/PiP; older incompatible entries correctly remain pending.

## Safety note
This update adds **conservative memory reconciliation**, not automatic retranslation or unconditional reuse of all historical translations. No new screen/text recording or background uploads are introduced.


## Legacy Memory Reconciliation 2.2 (follow-up addition)
- SQLite schema version 2 adds durable memory_legacy_associations links with foreign keys. Devices with schema-v1 SQLite upgrade in place transactionally; existing rows, history, settings and backup copies remain.
- **Live discovery:** exact source/language/context + independent current model result classifies a legacy row as validated_legacy (same English output) or superseded_legacy (alternative/new wording). Non-exact punctuation/spacing/case variations, rare one-character long OCR differences, and whole-word subtitle fragments are recorded only as **untrusted association suggestions**. Neither fuzzy suggestions nor previously stored old English text can produce a live cache hit.
- **Opt-in idle validation:** defaults OFF. If enabled, at most one historical entry per eligible foreground idle interval is independently translated on device. The user can request a manual batch of at most five. Work requires iOS 26+, installed language pair, no active capture/PiP/translation, no pending memory commits, normal/fair thermal state, and Low Power Mode OFF. No automatic execution in the background, no server upload, and no extra model calls during live captions.
- Only historical entries that pass current text-cleaning, slang and segmentation rules unchanged can create current-rule keys during idle retranslation. Entries using opaque protected context, malformed keys, or unsupported languages remain pending. Fresh results are persisted transactionally and the old translation remains inspectable, even when the new wording differs.
- The Live screen and diagnostics expose model warm-up states **Waiting**, **Warming**, **Ready**, **Failed**. The memory screen shows opt-in controls, reviewed count, pending older entries, and OCR/fragment suggestion counts. ZIP exports contain aggregate metadata-only association and idle validation counters, not source/translation text.
- Idle validation is cancellable on capture activation, rechecks capture, thermal, power and write contention after model work, and never commits a result after cancellation.
- Regression tests cover text variant discovery, whole-word fragment boundaries, meaning-changing substitutions, confirmation-only state changes, old row preservation, idle fresh-model commit and schema-v1 upgrade.
- Limits: a plausible word-level or fragment association is never accepted as proof; some old records can remain pending indefinitely. P95 latency and physical PiP display timing still require on-device video testing.
