# ScreenLingo v1.9.3 (build 74) — predictive admission and unified diagnostics

**Base**: v1.9.2 build 73 (`codex/screenlingo-v1.9.2-hybrid-reliability`). All work is on `codex/screenlingo-v1.9.3-prediction-diagnostics`; never edit `main`.

## Evidence and defect

v1.9.2 device sessions recorded zero speculative model completions in Hybrid and Low Latency, despite 54/145 speculative admissions. Backend stale-request rejection aligned with lost predictive work. The ownership check incorrectly required a new early subtitle to match the *previously displayed* confirmed subtitle, which is not how live subtitles advance. Low Latency regressed to approximately 347 ms median versus v1.9.1's 230 ms. Hybrid P95 improved to roughly 539 ms largely in the absence of competing speculative inference; genuine two-model concurrency is not yet validated.

The Diagnostics screen reads the Legacy-only `translate` timing series and Legacy-only speculative accounting in several graphs. New modes record timings elsewhere, leaving graphs stuck on “Collecting data…” and making some counters deceptively idle even while model work occurs.

## v1.9.3 implementation

1. **Correct predictive ownership**: A new unconfirmed caption may start speculation while the previous confirmed caption is displayed. It remains valid until a *new confirmed caption* supersedes it, a capture/mode reset occurs, explicit resource pressure intervenes, or it is committed. Recheck ownership just before backend admission after each suspension. Do not start stale requests, retry them, or allow their outputs to display. Already-running work can drain and seed exact-key ephemeral cache safely.
2. **Preserve the architecture**: Legacy behavior unchanged. Standalone Low Latency uses Low Latency for speculation and confirmation. Hybrid uses Apple Default speculation, Low Latency confirmed recovery, and bounded fallback. Both warm-up sessions stay reusable where safe; no assertion of physical model residency.
3. **Hybrid admission/backoff**: Keep the backend-occupancy guard to prevent fresh competing speculation. Penalize actually wasted model inference, not an internally rejected request or a memory-only speculative result. Count distinct candidate identity, avoid repeated OCR consuming backoff. Keep earlier v1.9.2 tail improvements and exact-key strategy caches.
4. **Unify Diagnostics**: Record completed model-service timing in the live `translate` series for all modes. Record successful caption-selection translation events independently, including memory-only selections. Make Overview, Speed, Pipeline, language origins, history, translation-per-minute chart, simple and detailed mode timing, textual report, CSV, and ZIP consistent with active mode. No invented samples, model execution for cache-only hits or zero durations; explain empty graphs if detailed collection is off/insufficient data. Display measured mode-specific real work instead of Legacy-only speculation counters.
5. **Privacy**: New events remain metadata-only; no OCR/translation text or keys in ZIP or diagnostics unless explicitly permitted by existing opt-in behavior. Preserve memory schema/history and App Group behavior.
6. **Tests**: Add positive next-subtitle, superseded candidate, post-reset rejection, speculative model readiness and backoff accounting regressions. Add static diagnostics routing tests for live model timings, mode caption events and mode-aware UI. Run full Xcode/macOS CI and IPA packaging.
7. **Acceptance**: Same-device Portuguese→English tests with three modes, identical temporary-memory settings, video, OCR area and order-balanced runs. Targets: restore Low Latency predictions and median toward v1.9.1 (230 ms); keep v1.9.2 Hybrid P95 (539 ms) as target while validating actual Apple Default and Low Latency overlap. No performance claim until on-device evidence. Diagnostic translation cards must show measurements with a completed model request in Hybrid and Low Latency; memory-only translations must increment selected counts but not fabricate model service measurements.

## Edge conditions

A model request may start before OCR confirmation of the next caption; a prior displayed caption must never invalidate it. If OCR confirms a different caption, only the still-unstarted work is rejected while an already-running model call safely finishes. If a caption is served wholly from memory, `translate` model-duration charts may legitimately have no sample; clearly identify such a case and show its selected translation count. Detailed timing requires Detailed Collection, which must be explained by the UI.
