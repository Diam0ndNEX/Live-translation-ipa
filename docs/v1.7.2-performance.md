## First implemented slice

When the model lane is busy, attempt synchronous assembly from exact current RAM
unit keys. Use the same cleanup, slang, dialogue splitting, protected tokens,
sentence segmentation, source/target/rule/model identity and final formatter as
ordinary processing. All units must exist and be nonblank; otherwise no cache
provenance is consumed and ordinary queued processing proceeds. No model, database
lookup or suspension occurs in the probe. No guessed Automatic source or partial
caption presentation. Existing generation/candidate/context, hold, pause, frozen,
fragment and PiP guards remain in the presentation path.

Existing whole-caption reuse remains the first choice. Both normal and temporary
banks support unit assembly; fresh-only and Retry bypass do not. Successful assembly
consumes the ordinary RAM/speculative/saved provenance, confirms eligible normal-mode
memory through the existing writer, and uses existing history policy on presentation.
The running model request remains serialized and is not cancelled at session level.

CaptionAssembly.complete is shared by queued model processing and RAM assembly.
It rejects missing/blank units instead of silently exposing source fragments.
RAM lookup durations and full synchronous processing duration are measured separately.
New exported counter: ramCaptionBypasses, distinct from exactCaptionHits.

## Expanded scheduling pass — build 57

The build-56 scope was too narrow to justify another user device test. The same
1.7.2 release now separates speculative TranslationSession ownership from the
retained confirmed session. Native Swift language mode is 5.0 (project.yml), no
strict/default isolation overrides; engine and session coordinator are MainActor.

Apple documents that Task cancellation and session cancellation differ: cancel()
attempts to stop all session work, and every future request on that session fails.
Source: https://developer.apple.com/documentation/translation/translationsession/cancel()

- A speculative request leases a reusable session for its source/target/model key.
- Confirmed replacement cancels its obsolete Swift task AND explicitly requests
  cancellation of only the active speculative session. Tentative OCR jitter retains
  cooperative cancellation/recovery; exact useful in-flight sharing remains enabled.
- The live drain still awaits the old request's return. No concurrent live requests,
  detached model work or assumption that cancel() immediately frees the OS model.
- A cancelled session is never retained for reuse. Successful speculative sessions
  remain warm; context reset prevents a late completion from restoring old state.
- Confirmed work uses its independent warm session. A failed older request cannot
  clear a different session installed while it was suspended.
- Existing completed-work recovery and optional incremental recovery remain intact;
  returned exact results may still be recovered after preemption, never presented
  as the old caption. Default model strategy/quality and OCR rules are unchanged.
- Export speculativeStopRequests, speculativeSessionsCreated and
  speculativeStopReleaseMs. Compare release delays AND new session creation costs;
  faster cancellation or lower device latency cannot be guaranteed by API contracts.
- Ownership regressions cover idempotent cancellation, no confirmed-handle mutation,
  no reuse after cancellation, successful warm reuse, key separation, context reset
  and stale completion isolation. Actual Apple model release requires device evidence.

Build 57 needs fresh full macOS CI verification. No new device test requested until

Confirmed in-flight sharing also uses the existing exact-unit/context policy. When
ALL units in an active confirmed batch are needed by the new caption, leave its
