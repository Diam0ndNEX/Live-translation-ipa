# ScreenLingo 2.4.0 (build 117): latency rebuild, first step

Base: `claude/screenlingo-v2.3.9`. Work branch: `claude/screenlingo-v2.4.0`. Draft PR #61 into the base branch.
Audit this is built on: `docs/v2.4.0-audit.md`.

**Nothing was compiled or run in chat.** The GitHub Actions run is the first real test. **No speed improvement is claimed.**
Every effect named here is UNVERIFIED until Diagnostics from Legacy, Hybrid Recovery and Low Latency on the same content shows it.

## 1. Mandate and limits (owner decision, 2026-11-10)
- Full authority over the code for this update; frozen-function and unchanged-text rules lifted; contract tests may be rewritten (section 6 lists what changed).
- Hard limits: no lower OCR accuracy, coverage or confirmation evidence; no skipped captions; a change that alters wording is a switchable, documented behaviour; Diagnostics stay metadata-only; no speed claim without three-mode Diagnostics.
- Goals, not claims: Legacy P50 under 350 / P95 under 800 ms, Hybrid under 300 / 600, Low Latency under 150 / 250.

## 2. What the audit found (short)
1. The "125 ms confirmation" contains the 120 ms OCR pass. The real floor of every caption is about one OCR pass.
2. In 2.3.9 the early (first sighting) packet reaches the app about 1 to 5 ms before the confirmed packet, so an early translation has almost no head start. About two thirds of first sightings are never confirmed. For Apple Default (about 270 ms, slow to cancel) those calls are still running when the real caption is confirmed. That is where Legacy's overlap, session-switch and queue waits come from.
3. In Hybrid the cost follows the change of model (first Low Latency call after Apple Default: 865 to 937 ms; first Apple Default call after Low Latency: 935 and 1265 ms), not the time gap. The 1.5 s switch guard cannot avoid it. Cause inside iOS: UNVERIFIED.
4. Low Latency's P95 is a confirmation tail (several OCR reads), not model or queue time. 2.3.9 does not record why.

## 3. What 2.4.0 changes

### Hybrid Recovery
- **Stays on one model for a run of captions** (`Shared/TranslationSystem+BackendPin.swift`, `HybridBackendPin`). Low Latency while its pack is installed; Apple Default when the pack is missing, or for 20 s after a Low Latency request returned nothing. Early work and recovery use the same model. The Apple Default admission gate, the adaptive backoff and the switch guard are not used while the pin is on Low Latency.
- **This alters wording**: fresh captions in Hybrid now have Low Latency wording. Switch: Experimental features, "Hybrid keeps one model" (`hybridPinnedBackend`, default ON, pinned at session start). OFF gives the 2.3.9 routing. Report column "switches on" shows `Hybrid pinned backend`.
- Side effect, same as in Low Latency mode: Low Latency results are not written to translation memory (only Apple Default results are), so Hybrid on Low Latency reads memory but adds nothing to it.
- The session prepared on the early lane is the pinned one.

### Legacy (and Hybrid while it uses Apple Default)
- **No early Apple Default call for a first sighting whose confirmation follows on the next frame.** The extension marks a first-sighting packet `pixelArmed` when the pixel check is ready, two reads are required, adaptive confirmation is off, and the confirmation wait ends with the OCR pass. The app then starts no early call; the confirmed packet, about one frame later, starts the call. Switch: "Wait for confirmation before early Apple Default work" (`deferArmedSpeculation`, default ON, pinned). OFF gives 2.3.9. Same model, same text either way.
- When the pixel check is not ready (more than four lines, too little ink, three or more reads required, longer wait under pressure) the early call starts as before, because then it has a real head start.
- Not changed: `process`, `drain`, `cachedCaption`, `extractTexts`, `selectBlocks` (still equal to the e94542ce text plus the listed 2.2.3 edits).

### Low Latency
- No routing change. It gets the shared changes below.

### All modes or Hybrid and Low Latency
- **Capture extension**: after a focused read finds changed text and is thrown away, the whole area is read on the next frame. Before, that read waited for the ordinary interval when no caption was pending. No read is skipped; no text is accepted sooner or with less evidence. (Focused reads exist only in Hybrid and Low Latency.)
- **Model call start** (Hybrid, Low Latency): the Apple call starts in a task that does not wait for the main actor (`backend_task_dispatch_ms` was P90 17 to 34 ms). The call is still not tied to Swift cancellation and the lane is still held until it returns. Changed: at the 4 s limit the session is asked to cancel and the request returns when the call returns, instead of answering early while the call ran on.
- **Language check**: "Refresh language check in background" now defaults to ON.
- **Diagnostics cost**: `structuredEvents` is no longer `@Published` (each append copied up to 6000 events and notified observers); both 6000-event rings are cut back in blocks of 256; the caption digest is computed once per caption, not per event. Exports are unchanged (windows of 5840 and 5872 events).

## 6. Tests changed (and why)
- `scripts/test_v223_contracts.py`: four assertions said the background language check defaults to OFF. They now assert ON (deliberate default change).
- `scripts/test_v230_contracts.py`: count of default-off pinned switches 5 to 4 (same reason).
- Seven scripts: version assertions 2.3.9/116 to 2.4.0/117.
- `scripts/test_three_modes.py`: new 2.4.0 block at the end (switches default on and pinned, pin wiring, deferral placement, unchanged OCR and confirmation evidence, forced re-read, model call, metadata-only fields, version). Put here because a new script needs a workflow step that cannot be pushed from chat.
- `Tests/ThreeModes/main.swift`: new Swift tests for `HybridBackendPin` and pinned Hybrid routing (early work on Low Latency, matching work awaited, recovery ignores the switch guard, fallback and hold, pin off unchanged, pin not used in Low Latency mode).
- No whole-function contract had to be replaced: the five compared functions were not edited.
- Not tested anywhere: the extension's frame scheduling, `ModeTranslationService` (needs the Translation framework), the Legacy drain. CI compiles them; nothing runs them.

## 7. UNVERIFIED (everything about speed and behaviour on a device)
1. That Hybrid on one model is faster and has no 900 ms calls. (Expected from the report; one run.)
2. That deferring armed early calls removes Legacy's overlap and session-switch waits, and does not cost latency when the pixel check rejects.
3. That the detached model call starts sooner in practice, and that a call that passes 4 s returns after `cancel()`.
4. That the forced re-read shortens real latency (the boundary does not show it; `rediscoveryLeadMs` does).
5. That the Diagnostics changes save measurable time, and that the Diagnostics screens still refresh as before.
6. Reaching any goal. From the audit: Legacy P50 under 350 and Low Latency P50 under 150 are not reachable without a shorter OCR pass or an earlier model start; nothing in 2.4.0 does that.

## 8. Not built (from the audit's list)
Trusted caption band, fast first pass for a head start, earlier read after a visual change, OCR from the pixel buffer with a region of interest, higher event caps. Each needs the new measurements first, and the first three can change what is read when, so they would need a switch and an owner test.
