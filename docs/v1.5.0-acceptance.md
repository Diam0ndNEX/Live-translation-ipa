# ScreenLingo 1.5.0 (53)

Based on 1.4.7 head ced58f60f6333e59374e01f4fc743952404b1130.

## Outcome and scope

Prioritize subtitle continuity and typical latency. The 1.4.7 device run had
slower median/mean/P90 and more confirmed-but-unpresented candidates than 1.4.6,
despite a lower successful-enqueue P95/maximum. Different memory reuse and fresh
translation workload prevent attributing all differences to the code.

Restore the 1.4.6 speculative policy: low-yield work retains alternate
opportunities instead of dropping to one in four. Preserve all 1.4.7 memory
management, selective legacy deletion and diagnostic features.

Recover an already-completed speculative batch when its candidate was replaced
but its context remains valid. Cache only complete nonempty exact-key sentence
results in bounded RAM; do not overwrite an existing cached result. Existing
keys include source, target, rules and protected-name mapping. No fuzzy reuse,
new model call, obsolete presentation, partial-caption presentation or direct
unconfirmed persistent write is permitted. Confirmed processing must still
independently request the exact key before any recovered output is used.

Settings/capture changes, RAM clear and memory mutations invalidate the context;
fresh-translation test and memory bypass reject recovery. Failed, incomplete,
empty or conflicting batches are rejected. Harvesting occurs synchronously on
the main actor after the original serialized model call returns: no concurrent
live translation calls or a new background queue. Existing RAM eviction applies.

specRetainedUnits is a cumulative numeric count of newly cached recovered units,
also available as interval deltas. It measures retention, not guaranteed reuse,
caption coverage or presentations. Superseded pipelines remain counted as
speculativeDiscarded; a later exact confirmed reuse remains a speculative hit.

## Verification and device acceptance

Pipeline regression checks cover alternate opportunities after sustained poor
yield, exact sentence recovery with repeated units, changed sentence/language/
rules/protected-context isolation, invalidated context, bypass and malformed
results. Diagnostic archive tests cover the new counter and privacy allowlist.
Existing pipeline, SQLite migration/fault tests, archive tests, storage benchmark,
Release app/extension build, version checks and IPA packaging remain required.

CI cannot establish real-device latency or visual quality. Compare 1.4.6,
1.4.7 and 1.5.0 on the same video section, timing, crop, settings, startup state
and comparable memory contents. Export before the next replay changes memory.
Consider fresh-test runs separately; fresh-test deliberately disables recovery.

Judge confirmed-but-unpresented candidates and observed subtitle continuity
alongside median/mean/P90, queue time, confirmed model calls, exact reuse and heat.
Do not accept a lower maximum as sufficient if normal latency or continuity is
worse. Enqueue timing excludes superseded work and is not physical screen time;
candidate counts are not unique subtitle-line coverage. Inspect the actual
video and PiP together to assess omissions, wording, order and flicker.

No automatic app-interface text classification, reduced OCR detail, narrowed
crop, relaxed confidence or reduced confirmation-read count is introduced.

## Research and decisions

- Apple documents that disabling recognition correction benefits performance
  but reduces accuracy. Keep accurate recognition, correction and current read
  requirements; reduce redundant scheduling/work rather than taking this trade.
  https://developer.apple.com/documentation/vision/vnrecognizetextrequest/useslanguagecorrection
- Apple documents requiredLocalEndpoint for a specific listener IP/port. Use it
  to make the existing localhost-only transport intention explicit.
  https://developer.apple.com/documentation/network/nwparameters/requiredlocalendpoint
- Apple documents that cancelling a TranslationSession attempts to stop its work
  and makes future requests fail. Apply explicit cancellation to disposable
  warm-up/idle sessions, not the reusable live session. No hard stop guarantee.
  https://developer.apple.com/documentation/translation/translationsession/cancel()
- SQLite documents WAL checkpoint blocking and optimize behavior. Retain FULL
  durability and existing actor ownership; do not introduce a blocking checkpoint,
  weaker sync mode or unmeasured schema change to chase small lookup costs.
  https://www.sqlite.org/pragma.html
- GRDB's own documentation discusses connection/queue ownership and statement
  caching hazards. Reviewed as an open-source reference; no dependency or copied
  code added. Keep the current bounded lookup implementation and remove duplicate
  health work before considering a new database layer.
  https://groue.github.io/GRDB.swift/docs/5.26/index.html

## Additional manual acceptance

Start capture, switch apps and return several times; verify packets and settings
continue without an artificial reconnect. Start capture during warm-up and idle
validation, verify live work wins, and inspect model/cancellation events. Switch
language pairs rapidly on an iOS 18 device. Replace/dismiss photos rapidly; the
latest request alone must own the text, error and loading indicator. Protect a
name beside literal placeholder-like text and an overlapping longer name.

Enable private mode, delete or edit a pre-existing library entry, restart and
check the explicit change persists while new private translations remain absent.
Exercise explicit clear and legacy deletion cancellation/commit/restart. Review
diagnostic median/mean/P90 alongside unpresented candidates and actual PiP/video
continuity. A smaller tail alone is not release acceptance.
