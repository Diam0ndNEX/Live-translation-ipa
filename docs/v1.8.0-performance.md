## Goal fixed before device measurements

The release must improve unknown-content/temporary-memory performance and ordinary
saved-memory performance independently. A fast saved-memory run cannot establish
uncached performance. A faster median cannot conceal a worse tail or missing captions.

The strict release gate requires ALL end-to-end median, mean, P90 and P95 statistics
at least **25% lower in temporary-memory mode** and **10% lower in normal mode** than
EACH supplied older baseline in its own cohort. Minimum 50 enqueues per recording.
Hardware, OS, settings and RAM starting populations must match. Compare the same
video boundaries and startup/thermal conditions. Required independent evidence:
wording, coverage, order, flicker, long-session reliability, thermal/battery, saved
memory surviving upgrade and isolation of normal/temporary memory banks.

These are acceptance targets, not measured results or a promise from CI.
The existing 40-cell/90% diagnostic comparison remains available separately; it
must not be confused with the new user-visible, end-to-end release decision.
Neither tool measures a video's first subtitle frame or physical PiP presentation.

## Implemented mechanisms

1. **Immediate complete RAM assembly even when the model is idle.** Previously the
   bypass required `busy`, so a ready caption still needed another scheduled Task.
   Existing exact keys, complete assembly, OCR confirmation and presentation guards
   apply. Automatic source continues through ordinary language resolution.
2. **Bounded saved-memory probe around model work.** While a model call is in flight,
   a separate read-only coordinator looks up missing exact current-caption units.
   It coalesces duplicates, accepts at most 32 keys, and stops at the first miss,
   blank, timeout or unavailable result. Existing store lookup has an 8ms deadline.
   Stored hits populate only the captured normal RAM bank; ordinary complete-caption
   assembly consumes saved provenance and performs presentation. No second model
   request or new database connection is introduced. A miss returns model priority.
   Generation, context, bank, rules, privacy, mode and queued-caption validity are
   checked before and after every await. Cancellation is an additional signal;
   lease invalidation rejects even cancellation-ignoring storage completions.
3. **Completed speculative responses unblock waiting confirmed captions.** Use the
   existing indexed incremental response mapping for installed-model batches.
   Once a confirmed replacement is waiting, every already returned complete exact
   unit can enter volatile reuse; complete assembly still requires all current units.
   Without a waiting caption, the existing `incrementalBatchRecovery` experiment
   governs early speculative retention. Its stored key and OFF default remain.
   Single-response and iOS 18 fallback behavior is preserved.
4. **One warm session owner at a time.** Speculation can borrow a compatible warmed
   confirmed handle, removing it from the confirmed slot before use. A successful,
   context-valid lease can transfer back. Explicitly cancelled sessions cannot
   transfer, and no session is retained by both owners. Routine subtitle replacement
   now cancels only the Swift Task. Global context invalidation still permanently
   retires the active speculative session. This addresses 27 explicit stops with
   zero recorded cancelled batches and 28 session creations in the latest temporary
   run: destroying warm sessions had no demonstrated cancellation payoff. A result
   that fails or belongs to a changed context still cannot return a warm handle.
   Live model execution remains serialized; there is no assumption that cancellation
   immediately releases OS work.
5. **Measured speculative work budget.** Track up to 32 pipelines in each existing
   isolated RAM bank, regardless of diagnostics. After eight completed pipelines
   and four waits >=80ms, if total blocking >=640ms and exceeds half the measured
   reused model-duration credit, admit one in three speculative opportunities.
   New useful pipelines age old debt out. The existing adaptiveSpeculation opt-out
   disables this budget; confirmed work is never gated. This is a policy estimate,
   not a claim of counterfactual time saved. Device A/B acceptance is essential.
6. **Capture readiness in Live.** Always-visible SF Symbol, text and color distinguish
   idle, requested, connected-before-frame, active, lost and stopped. Only receipt
   of a video-frame counter authorizes active. Existing five-second heartbeat expiry
   and a best-effort explicit stop clear readiness; a cancelled picker expires after
   30 seconds. Paused translation/frozen output have separate text. Session IDs
   isolate an obsolete stop. Metadata is optional for older extension compatibility.
   No high-frequency polling. Heartbeat expiry now invalidates pending output too.
7. **Diagnostic accountability.** Four privacy-allowlisted numeric counters:
   savedUnitsPrefetched, savedCaptionBypasses, speculationBudgetSkipped and
   warmSessionTransfers. `ramCaptionBypasses` now covers idle as well as busy
   assembly, and its summary label reflects that. Evidence card shows actual version.

8. **Availability/session identity is shared.** `refreshStatus` previously wrote
   `source>target`, while `pairStatus` read `source>target|strategy`. Both now use
   the same ephemeral identity as warm/live sessions. An older strategy's suspended
   availability scan cannot publish over a newer strategy. Unsupported-OS model
   selection remains default. Durable memory keys/digests are unchanged.

9. **Rejected write admissions remain retryable (build 62).** RAM no longer marks
   a key handled before `queueMemory` accepts it. Remember OFF, privacy/test-mode
   refusal and a full pending queue cannot create a false accepted-write marker.
   A proven saved hit still avoids redundant writes. Complete caption results carry
   bounded volatile key metadata so a later confirmed reuse can retry admission;
   an evicted unit never forces a fresh model request merely to display an already
   complete cached caption. Normal accepted paths retain their fast return.
   Cache-hit promotion now uses the same structural unit eligibility as fresh
   promotion. No RAM hit becomes independent legacy-validation proof.
   Tests include rejected/accepted/duplicate/proven-saved admissions and a real
   SQLite queue-full recovery plus reopen with prior memory preserved.

## Memory invariants

No database schema/version, path, migration receipt, SQL write, stored key, rule
digest, model strategy, retention capacity, history policy or user setting is reset.
Normal and temporary banks remain separate. Temporary mode cannot run the saved
probe, persist translations or insert history. Saved hits never provide independent
legacy-validation proof. Unconfirmed units are RAM-only until independently confirmed
through the existing path. Main and the previous candidate remain available.

## Research

Apple's primary API contracts reviewed October 29, 2026:
- https://developer.apple.com/documentation/translation/translationsession/cancel()
  Cancellation attempts to stop work; future requests on that instance fail.
- https://developer.apple.com/documentation/translation/translationsession/translate(batch:)
  Responses arrive incrementally and must be matched by clientIdentifier.
- https://developer.apple.com/documentation/translation/translating-text-within-your-app
  Batch sequence responses can arrive out of order.
