# ScreenLingo 2.7.0 (build 131): iPhone and iPad interface

Branch `claude/screenlingo-v2.7.0` from `claude/screenlingo-v2.6.5`. Owner request: refine and optimize the UI and UX for iPhone and iPad, check that everything is wired, debug deeply, add features where needed, one update.

**Nothing was compiled or run in chat.** The GitHub Actions run is the first real test. Every layout below is UNVERIFIED until the IPA is installed on an iPhone and an iPad. No speed claims: no hot path was edited (`SampleHandler`, `TranslatorEngine`, `TranslationSystem` and the five pinned functions are unchanged).

## What was read
All of `App/UI/` (Translate, Library, Languages, Kit, Model), `ScreenTranslatorApp`, `AppRouter`, `Platform`, `Tokens`, `Feedback`, `EngineSlice`/`ObjectSlice`/`EngineHandle`, `SettingsViews` (home), the top of `DiagnosticsDashboard`, `CustomizationViews` (Timing), `OnboardingView`, the top of `AreaEditor`, `PiPHost`, the OCR scaling in `SampleHandler`, `project.yml`, the UI lints and contract tests that touch these files. Not read in full: Diagnostics pages and cards, Test runs views, Memory view, Presets, Settings sub-pages, engine parts.

## Problems found (by reading code)
| # | Problem | Fix |
|---|---|---|
| 1 | iPad was locked to portrait outside Translate/Focus; no `~ipad` orientations, so Split View / Stage Manager / windows could not work and a keyboard case in landscape forced a rotation | iPad returns `.all`; `UISupportedInterfaceOrientations~ipad` lists all four; `TARGETED_DEVICE_FAMILY "1,2"` stated explicitly |
| 2 | Every iPad screen was a 640 pt phone column | Translate: two columns from 760 pt width (1000 pt at accessibility sizes); Library and Settings: `NavigationSplitView` in regular width; Diagnostics: 980 pt column |
| 3 | `SettingsView` and `ResponsivenessSettings` observed the whole engine; all tabs stay alive, so Settings redrew on every engine change during capture | `@EngineFacts(SettingsSummaryFacts.read)` and `@EngineHandle`; content style/speed refresh from a throttled UserDefaults notice |
| 4 | Return on the compose keyboard (label Send) only inserted a new line: a vertical `TextField` never calls `onSubmit` | one typed line break sends; pasted text keeps line breaks; Command-Return sends |
| 5 | A notice with Undo stayed up to 6 s after Undo, so Undo could run twice | the action closes its notice first |
| 6 | Recent rows on Translate did nothing; their relative time ticked every second | a row opens the item in Library (`AppRouter.openLibraryItem`), context menu Copy / Open; static relative time |
| 7 | Reading-area picture had a fixed 9:19.5 phone shape | `ScreenShape.aspect` from the current screen (iPad 3:4 or 4:3) |
| 8 | Session sheet: Pause translating and Restart session timer worked with no session; pausing while idle made the next session start paused | disabled without a session (Pause stays usable to turn it off) |
| 9 | Setup Start button: an 88 pt button scaled to 0.6 inside a 106 pt box | real 54 pt size |
| 10 | Text said "on your phone" on iPad | "on this device" |

## New
- Sidebar-adaptable tabs (iOS 18 `Tab` API); iPhone keeps the tab bar.
- Hardware keyboard (`App/UI/Kit/KeyCommands.swift`): ⌘1–⌘4 tabs, ⌘, Settings, ⌘L languages, ⌥⌘L swap, ⇧⌘F Focus mode, ⇧⌘I Session, ⇧⌘P floating window, ⌥⌘P pause, ⇧⌘H hold, ⇧⌘C copy, ⇧⌘R read aloud. Focus mode: Esc, Space (hold), ⇧⌘C, ⇧⌘R, ⌘+ / ⌘−. Each calls the same method as the button.
- Drop a picture or text on the compose bar (iPad Split View / Slide Over / other apps).
- Library: context menu (Save, Copy, Listen, Share, Delete); deleting the selected item clears the iPad detail; export uses the checked rows only while selecting.
- Pointer hover highlight on every `PressableStyle` button.
- Focus mode, area editor and Test runs open with `.presentationSizing(.page)` (large on iPad; no change on iPhone). Focus mode "Full" width stops at 900 pt on iPad.
- Notices at most 560 pt wide.
- UI screenshot workflow also shoots a 13-inch iPad (not in QUICK runs).

## Tests changed (deliberately)
- `test_ui_no_carryover.py` U2: counts `value: AppTab.x` (Tab API) as well as `.tag(AppTab.x)`.
- `test_experimental_settings.py`: matches the start of `PresetsLinkRow(store: engine.presets` (the call gained iPad arguments).
- `test_v221_contracts.py` U3: the setup button call is `StartButton(live: broadcastDone, size: 54) { engine.captureRequested() }`.
- Version asserts moved to 2.7.0 / 131. New 2.7.0 block at the end of `test_three_modes.py`; one router check in `Tests/Navigation/main.swift`.

## Not done / open
- Multiple windows stay off on purpose (`UIApplicationSupportsMultipleScenes` absent): each window would create its own engine and loopback server.
- Settings sidebar rows on iPad are buttons that fill the detail column; whether the system highlight and back behaviour feel right needs the device.
- Whether a `List(selection: Set)` in the iPad Library sidebar selects on a plain tap without edit mode is expected from SwiftUI behaviour, not checked on a device.
- Hidden-button keyboard shortcuts are a known SwiftUI pattern; whether ⇧⌘H is free on every iPadOS version is not checked.
