# ScreenLingo 2.2.3 — Latency specification (draft)

Status: draft written 2026-11-08 from the 2.2.2 build 105 test report and a read of the 2.2.2 code. Nothing in this file has been compiled or run. Every speed idea is UNVERIFIED until Diagnostics data (same content, Legacy, Hybrid Recovery, Low Latency) shows it.

Base: branch `claude/screenlingo-v2.2.2`. Work branch: `claude/screenlingo-v2.2.3`. Draft PR into the newest codex branch, never `main`. Version 2.2.3 is a proposed name and needs the user's OK.

## Goal
Lower latency in every mode with unchanged translation quality: same model output, same OCR quality, same confirmation evidence, same text coverage.

## Evidence: 2.2.2 b105 test (iPhone18,2, iOS 27.0.1, pt>en, movie, Temporary Memory, all Nominal)
First OCR sighting to PiP enqueue, ms:

| Mode | n | P50 | P95 | max |
|---|---|---|---|---|
| Legacy | 107 | 457 | 860 | 1273 |
| Hybrid Recovery | 86 | 465 | 917 | 1158 |
| Low Latency | 93 | 177 | 254 | 439 |

Caveats: same-content overlap only 45–49%; one session per mode; S2/S3 hit the 2,400 mode-event cap (early events missing); Hybrid P99 blank. Treat as indicative.

Compared with older builds (1.9.x, project docs): Legacy P50 best of the window; Low Latency P50/P95 far below the 240/445 plateau; Hybrid P95 lower than 1.9.3–1.9.8 but P50 still above the 1.9.2/1.9.3 values (355/382).

## What the code and data say
Corrections to earlier readings: `deliveryFilteringMs` in Hybrid (P50 236, P90 571) matches Hybrid confirmation-to-PiP (P50 231, P90 546), so it is the wait for the Default model booked under another label, not a separate cost. The `hybrid_switch_guard_*` value is the gap since the last Default return, not a delay.

1. Floor in all modes: OCR (~105–111 ms) and confirmation (~117 ms) are flat across modes and builds. Fast OCR was OFF in this test.
2. Low Latency: model call ~54 ms. Cost is the OCR/confirmation floor.
3. Hybrid:
   - The switch guard (window 1500 ms) sends confirmed recovery to Apple Default when a Default call ran within 1.5 s. Only 2 of 14 recoveries used Low Latency. Default confirmed service ~331–358 ms.
   - Default speculation never finished before confirmation (0 "match ready" captions); every match was "in flight" and waited for the remainder (confirmation-to-enqueue P50 316 ms).
   - Admission throttle (3 wasted speculations skip the next 8) throttled 10 captions in a row (c10–c18), forcing recoveries after confirmation (P50 408 ms).
   - 5 `hybrid_default_default_overlap` events (confirmed Default starting while the speculative lane also ran Default); effect unmeasured.
   - Low Latency is NOT a quality-neutral substitute: the app states wording may differ from Legacy.
4. Legacy:
   - 63 of 107 captions queued behind an in-flight speculative call (queueBehindSpeculationMs P50 130, P90 396).
   - speculativeStopReleaseMs P50 96, P90 376 (n=44): after preempting a speculation the confirmed call waits for the backend to release. Source comment: Swift cancellation may leave Apple's request running.
   - Speculation matched confirmed text on ~22% of captions; 65 captions were "confirmed fresh" (P50 485 ms), 16 "legacy recovery" (P50 548 ms).
5. Availability check: cached for 30 s (`installedCheckTTL`); the call after expiry costs ~43 ms (modeAvailabilityCheckMs P95 43). Tail only.
6. Memory: lookups cost 0 ms in every mode with 0 timeouts, so the planned second read-only SQLite connection is NOT needed.

## Changes (each behind a runtime A/B switch, default = current behaviour until measured)

| ID | Mode | Change | Quality impact | Risk |
|---|---|---|---|---|
| L1 | All | Run the existing Fast OCR experiment as an A/B arm (no code change expected beyond making it switchable at runtime if it is not) | May change OCR accuracy. Measure missed captions, misread text, coverage. | Medium |
| L2 | Legacy | Let the confirmed call use its own lane when the in-flight speculation has different text (Hybrid already has two lanes) | None expected: same model, same strategy | Two simultaneous Apple Default calls may slow each other. Check test_three_modes.py and legacy contract tests first |
| L3 | Hybrid | Start Default speculation earlier and relax the admission throttle (e.g. decay by time, smaller skip count) | None expected: same Default output | More wasted Default calls could add contention |
| L4 | Hybrid | Re-evaluate the switch guard window and the 220 ms post-Default settling wait together | None expected: guard changes which model recovers only when Low Latency was already allowed; confirm no wording change vs current Hybrid | May reintroduce ~900 ms recoveries |
| L5 | All | Refresh the language-availability check in the background before the 30 s TTL expires | None | Low |

Out of scope unless the user approves after data: replacing Hybrid's Default with Low Latency, lowering OCR resolution or confidence, weakening confirmation, skipping hard captions.

## Code rules (from project instructions)
- Source-level contract tests compare whole functions with older commits (`scripts/test_*.py`, including `test_v221_contracts.py`, `test_v222_contracts.py`, `test_three_modes.py`, `test_v199_performance.py`). Read them before editing SampleHandler, TranslatorEngine, TranslationSystem.

## Measurement plan
Same video, device, preset, language pair and memory state. At least 3 runs per mode per arm, counterbalanced order, Nominal and Fair separately if available. Report P50/P90/P95/P99/max with n. Check subtitle coverage, misread/missed captions and PiP flicker next to speed. Quality guardrail: a change that helps one mode and hurts another is disabled.

## Acceptance
- CI green (native Swift, source tests, SQLite migrations, Release build, unsigned IPA) is necessary, not proof of speed.
- Each kept change shows a matched-content improvement and no quality or P95 regression.
- Unmeasured changes stay labeled UNVERIFIED and default OFF.
