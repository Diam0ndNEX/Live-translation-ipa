# ScreenLingo 1.4.5 (49): latency and continuity

## Change contract

Based on PR #16 / `2b897d7e35992fd2c655a8084d53f0f359e4d462`, not main.
The 1.4.4 device run had 421ms median, 715ms P90, 1051ms P95,
3023ms maximum first-OCR-to-enqueue, and six confirmed-unpresented
supersessions. Four recorded >1200ms enqueues occurred near capture startup.
These are observations, not an established root cause or a sentence-coverage measure.

Preserve accurate OCR, selected detail, language correction, confidence floors,
the required number of independent reads, whole-caption assembly/order, source
selection, glossary/protected words, rule-aware memory keys, transactional
persistence, private-session behavior, and physical-presentation caveats.

## Implementation and expected mechanism

| Boundary | Change | Constraint / evidence needed |
| --- | --- | --- |
| Capture/confirmation | A pending Movie read may use max(120ms, previous OCR cost), capped at the existing planned interval. It is a brief scheduling burst, not fewer reads. | Disabled under Cool, thermal/power or queue pressure. No repeated recognition of the same sample buffer. Test recognition coverage and temperature. |
| OCR | Reuse the accurate Vision request while source language, correction and crop span match. | The existing lock serializes request use; every frame still performs fresh recognition. No resolution reduction or tighter implicit crop. |
| Startup model | Pre-capture warmup includes a short word and one subtitle-length sentence in one batch on the retained session. Remove the competing warmup launch at capture connection. Check cancellation after availability. | Synthetic translations never reach memory, history or PiP. Benefit requires on-device measurement; two warmup inputs may increase preparation time. |
| Speculation | Recent 32-pipeline outcomes independent of diagnostics; after 24 completed observations, at least 50% discarded with fewer than 18% reused pipelines probes alternate opportunities. | Confirmed work is never throttled. Sentence hits cannot inflate pipeline usefulness. Old scenes age out. |
| Confirmed handoff | Preserve early absolute 450ms window; at age 450–900ms allow at most 120ms once. Keep one newest packet without renewing the deadline; replay bypasses protection. | Tradeoff: a new confirmed caption can wait up to 120ms in the later window. Stop at 900ms old-confirmation age; pending replay expires at 1.2s. Do not promise zero supersessions. |
| Delivery/replay | Split actual packet reception from local content replay. Clear deferred work on context invalidation. | Replay must not refresh capture heartbeat, recount transport/OCR packets, or renew protection. Rotation, pause, frozen output and language/rule checks remain. |
| PiP | Recycle released pixel buffers through a size-specific pool; retain format descriptions at equal dimensions; render a resized new caption once. | Never overwrite an enqueued buffer. Allocation fallback stays available. Preserve image/font/colors; keep existing DisplayImmediately and heartbeat. |
| Enqueue evidence | Render returns success; engine does not mark a failed preparation as a successful caption enqueue. | Buffer enqueue is still not proof of physical display. A synchronous renderer failure reports retry and is separately counted. |
| Diagnostics | Export matched confirmation/delivery/queue/processing/hold/render distributions, actual API submission categories, handoff replay/expiry/failure and existing whole-session counters. | Bounded samples, overlapping stages, no subtitle text, no identifying paths. |

## Research and choices

Primary Apple references consulted:

- https://developer.apple.com/documentation/vision/recognizing-text-in-images
  Accurate and fast recognition use different paths; language correction helps
  recognition. Retain accurate recognition and correction rather than exchange
  quality for speed.
- https://developer.apple.com/documentation/translation/translationsession/preparetranslation()
  Preparation requests language installation without performing translation.
  Real synthetic translation is retained for model exercise; it is best-effort.
- https://developer.apple.com/documentation/translation/translating-text-within-your-app
  Batch APIs reduce repeated calls; incremental responses require identity mapping.
  ScreenLingo already batches/coalesces missing sentences. Keep atomic caption
  assembly rather than display partial sentences out of order. Streaming an
  already atomic caption would not eliminate waiting for its final required unit.
- https://developer.apple.com/documentation/coremedia/kcmsampleattachmentkey_displayimmediately
  Immediate display scheduling already exists in the renderer. Retain it; do not
  claim it as a newly added latency fix or physical display measurement.
- https://developer.apple.com/videos/play/wwdc2014/513/
  Pixel-buffer pools recycle storage after all holders release a buffer.
  Use a pool rather than mutate a buffer still owned by the display pipeline.

No tighter automatic subtitle crop, fast OCR, reduced image detail, confidence
relaxation, fewer confirmation reads, approximate translation-memory reuse,
partial caption output, or unbounded model concurrency is introduced.
Memory lookup in build 48 was already <0.31ms at P95, so the database's matching
and safety rules are preserved. No speculative cache schema/migration change.

## Accounting compatibility

`modelBatches` remains the old confirmed logical-batch counter. New
`actualModelBatches` counts runBatch API submissions and equals
`confirmedModelBatches + speculativeModelBatches + warmupModelBatches`.
It excludes separate idle-validation workers. Retries are separate actual calls.
`first30sModelBatches` and the legacy `coldModelBatches` alias are completions of
foreground/speculative work submitted in the first 30 capture seconds; neither
proves a cold load. Database health totals may include prior sessions, so an
initial `legacyVerified` delta is not proof that all verification occurred now.
Some decision counters require detailed collection. Stage distributions are
bounded matched enqueues, not an additive budget or video ground truth.

## Verification and device acceptance

CI: existing Swift pipeline regressions plus new confirmation scheduling,
handoff deadline and rolling speculation recovery tests; SQLite migration/fault
tests; diagnostic archive privacy/allowlist tests; existing 3k/25k benchmark;
Release iOS application + extension compile and version verification; IPA.

This execution environment has no swiftc or Xcode. Local diff/config checks do
not substitute for CI. Record the final CI status before claiming a built IPA.

On iPhone, compare the same five-minute clip against build 48 with matching
settings and controlled starting memory. Repeat at least three times, record
the screen, and retain diagnostics. Separately run a short fresh-translation
clip so memory reuse cannot mask model performance. Compare first-30s vs later
median/P90/P95/max; startup model submissions; confirmed supersessions;
handoff duration; speculative usefulness; thermal/power; failed writes and
enqueue failures. Visually verify wording/order/coverage/flicker, moving captions,
small text, multiple lyric rows, fast dialogue, pause/freeze/rotation and language
changes, repeated clear/start/stop, private mode, and resizing/theme changes.

Reject an optimization that lowers latency while degrading those checks. No
percentage improvement, no guarantee of lower latency in every stage, and no
quality parity claim is made before the device evidence exists. OS OCR/model
execution and actual physical PiP display are not fully controlled by the app.
