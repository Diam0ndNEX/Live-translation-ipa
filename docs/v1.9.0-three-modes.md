## Architecture and invariants

- One persisted `translationSystem`: legacy / hybridRecovery / lowLatency. Explicit old Hybrid wins over low-only as the old implementation did; explicit low-only maps to Low Latency; missing/corrupt/future maps to Legacy without deleting its value or unrelated data. Active and pending are separately visible. No mid-capture mode transition.
- Legacy retains reference `process`, `drain`, `speculate`, cache assembly, OCR filtering and block-selection code. Old low-latency flags no longer route Legacy. New modes intercept before Legacy candidate/fuzzy/scheduler policy.
- `ThreeModeCoordinator`: MainActor atomic selection latch; full session/caption/revision/language/rules/content identity; NFC and whitespace normalization only. Numbers, negation, punctuation, prefixes and case remain significant. No fuzzy acceptance.
- Independent preferred-memory lookup occurs before inference wait. LL results stay in a bounded 256-unit strategy-specific session cache; preferred RAM/SQLite entries are never overwritten by LL. Only confirmed default-strategy outputs can use the existing durable admission/writer. Temporary/fresh/private policy remains enforced by the existing writer.
- One actual request per speculative/recovery lane. Cancel requests do not release a slot. Slots release only when Apple's request returns. Confirmed waiters are cancellation-aware and bounded; no accumulating model sessions. Memory never waits for a model slot.
- Low Latency explicitly requests low latency for all new model calls and same-strategy retry. No default enrichment/refinement/preparation. Compatible preferred memory retains its existing unknown/default provenance; it is not relabelled as low latency.
- Hybrid default speculation reuses matching ready/in-flight output. Mismatch/absence/failure admits low-latency recovery immediately, independently of speculative unwind. Hybrid alone allows default fallback on LL failure. Only one result selects per confirmed revision. Genuine source correction creates a new revision.
- Initial matching Hybrid deadline: **700 ms total since speculative admission**, derived conservatively by rounding the reference temporary run's observed confirmed-model maximum 653.734 ms. It is not an added 700 ms confirmation delay or a promised portable latency budget. After at least 5 observations per strategy, remaining wait is bounded by measured median remaining default service, measured recovery service and 250 ms. Actual contention/thermal/language tuning remains a device acceptance gate; Hybrid stays opt-in.
- Low Latency shares matching work without the Hybrid grace policy; a 4 s hung-request deadline cancels the old lane and allows one bounded same-strategy retry through recovery. Model calls time out after 4 s, but their slots remain occupied until the underlying call returns.
- Existing focused OCR/tracked-region/full rediscovery logic is retained. New-mode speculation is gated by credible OCR, test mode and thermal state. No changes to Legacy OCR scheduling.

## Diagnostics and validation boundaries

Versioned optional `translationModes` in session.json/ZIP preserves older imports. Bounded metadata timeline includes session/caption hash, source revision, language, source SHA256 fingerprint, monotonic origin/time, strategy requests, memory probes, matching/unfinished/mismatch paths, recovery decisions, queue/service times, selection, enqueue, stale/missing/errors and thermal state. Archive writer revalidates reasons, hashes and language codes. Enqueue distributions include count, mean, median, P90/P95 (with existing small-sample suppression) and observed maximum. A retained session is not labelled measured model warmth.

PiP enqueue is **not physical presentation**. Missing counts describe confirmed superseded/failed work, not OCR-invisible ground truth. Device comparison must use matched content/language/settings/thermal and isolated equivalent memory snapshots, counterbalance order and separate memory, successful speculation, confirmed fresh and recovery paths. Assess multilingual quality independently for names, numbers, negation, prefixes and punctuation. Do not clear the user's database.
