# ScreenLingo 2.1.0 – Ground-up UI/UX specification (§13)

Status: owner-approved direction, written 2026-11-08 after builds 87–90 were rejected. Supersedes the screen layouts in
§12.5 of `v2.0.0-ui-ux-overhaul-specification.md`. §12.8 (hard boundaries), §12.9 (feature parity) and §12.0.1
(zero carry-over) stay binding.

## 13.0 Why builds 87–90 were rejected (read first)

The owner's verdict on build 90: "they still look pretty rough, some are too big, not really creative, the subpages
seem really stale, you are still using the old code and just putting a skin on it."

That is accurate. Builds 87–90 kept the 2.0.0 screen structure (stacks of cards, a tab per old feature, 16 settings
pages behind tiles, Diagnostics with a pinned header) and changed fills, radii, fonts and shadows. A restyle cannot fix
a structure problem. Two process failures made it worse: nobody saw the result before it shipped (no screenshots, only
text tests), and a syntax error that broke CI in builds 88–89 shows the code was never compiled before pushing.

**2.1.0 is a rebuild of the view layer, not a restyle.** New information architecture, new components, new screens, old
views deleted. The engine, stored data and settings keys stay.

## 13.1 Design principles (with where they come from)

1. **Content first, chrome second.** Apple's Liquid Glass guidance: controls should "elevate and distinguish the content
   beneath them", hierarchy comes from spacing, size and behaviour rather than colour or effects, and glass is for
   depth and feedback, not decoration ([Create with Swift: Liquid Glass hierarchy, harmony and consistency](https://www.createwithswift.com/liquid-glass-redefining-design-through-hierarchy-harmony-and-consistency/),
   which quotes Apple's HIG; I did not read Apple's own pages directly).
   Consequence: the translated text is the biggest thing on the main screen; bars are system bars.
2. **Navigation should adapt to context.** Same source: tab bars should respond to context and may hide or simplify.
   Consequence: the tab bar minimises while scrolling and while a live session shows full-screen text.
3. **Signifiers, mapping, feedback, constraints.** A critique of Apple Translate praises the swap button sitting between
   the two languages (position maps to effect, the arrow reverses as feedback) and the camera view that removes the
   swap because that mode only goes one way ([Pratt IxD critique of Translate](https://ixd.prattsi.org/2026/09/design-critique-translate-iphone-app/)).
   The same critique says saved and recent items must not share one list because users think of them separately.
   Consequence: the language pair is the typographic centre of the main screen; Saved and Recent are separate in Library.
4. **Progressive disclosure, with a visible cue.** Show essentials first, put the rest one tap away, but never hide
   a feature with no cue, and do not guess which features matter most ([UX Planet: progressive disclosure for mobile](https://uxplanet.org/design-patterns-progressive-disclosure-for-mobile-apps-f41001a293ba)).
   Consequence: Diagnostics opens on one answer, with every lens listed as a row that shows its live value.
5. **Use the platform.** Prefer system components (`List`, `Form`, `NavigationStack`, `.searchable`, `Menu`,
   `ContentUnavailableView`, `Gauge`, Swift Charts) and system behaviour (large titles, swipe back, Dynamic Type).
   Custom components exist only where the product is unique (§13.4.3). A custom card library is what made 2.0.0 look
   hand-made and stale.
6. **The app is a remote control for something that happens in other apps.** Its job is to answer in a second:
   "is it running, what is it saying, how do I fix it." Everything else is secondary.
7. **Settings that show what they change.** Every setting group that affects the look or behaviour of the floating
   caption gets a live preview at the top of its page.

## 13.2 Product model: one state machine

Add `SessionPhase` (view-layer enum, derived from existing `CaptureSnapshot`; no engine change):

`idle` → `starting` (broadcast sheet opened, no frames yet) → `live` → `paused` → back to `live`; `attention(reason)` for
lost capture, timed out, missing language pack, floating window closed.

Every screen answers "what phase are we in" the same way: one glyph, one word, one colour rule (accent for live,
neutral for idle, amber for paused or attention, red only for a failure that stops translation). Colour is never the
only signal. No score or colour is shown without evidence (R7).

## 13.3 Information architecture

Four tabs: **Translate · Library · Diagnostics · Settings**. (Languages is no longer a tab: it is a sheet opened from
the language pair and a page under Settings > Translation, one implementation for both.)

| Old (2.0.0) | New (2.1.0) |
|---|---|
| Live tab | **Translate** tab (idle, starting, live, paused and attention are states of one screen) |
| Languages tab | `LanguageSheet` from the pair on Translate; also Settings > Language packs |
| Reader sheet | **Focus mode** of the live caption on Translate (full-screen text, same screen) |
| Text & photos sheet | **Compose bar** on Translate (type or paste) with Photo and File buttons; results appear as a card |
| Status and More sheets | Merged: **Session sheet** (state, timer, pause, window, report) and **Tune sheet** (area, scene, size) |
| Capture area sheet | Full-screen `AreaEditor` pushed from Tune |
| Presets | "Scenes" chips on Translate; manager under Settings > Scenes |
| Diagnostics with chips | Diagnostics = Overview + a list of lenses, each a pushed page (§13.5.4) |
| 16 settings pages as tiles | Settings as one grouped list in five groups (§13.5.5) |
| Onboarding, 3 steps | One checklist screen with live checks (§13.5.7) |

## 13.4 Visual system

### 13.4.1 Rules (these become lint rules in §13.8)

- **One surface level per screen.** Content sits on the page background. Group related rows with the system inset
  grouped list. A card (single rounded container) is allowed only for one hero object per screen. No card inside a card.
  No strokes on surfaces. No shadows in dark mode. No gradients on surfaces (only on the Start button glow).
- **Size discipline.** No element except the live caption may be taller than 28% of the screen height. No two-column tile
  grid anywhere in Settings. Rows are 44 pt (one line) or 56 pt (two lines), never more unless Dynamic Type grows them.
- **Type ramp (Dynamic Type styles only).** Nav large title 34 bold; hero numerals 48–56 rounded semibold; live caption
  28–44 auto-fit; title2 22; headline 17 semibold; body 17; subheadline 15; footnote 13; caption 12 is the minimum.
  `caption2` and fixed sizes below 12 pt are banned. At most four distinct sizes on one screen.
- **Spacing.** 4 pt grid. Page margin 20 pt. Gap between groups 24 pt. Bottom content inset equals the tab bar height
  (use `safeAreaInset`/system scroll insets) so nothing is cut off (R4).
- **Colour.** Neutral base, one user-chosen accent, semantic colours only for state. Dark: true-black page, `#1C1C1E`
  grouped surfaces (use system semantic colours so Light and Increased Contrast work). Light: system grouped backgrounds.
  Contrast at least 4.5:1 for text, 3:1 for icons and the Start button.
- **Motion.** One spring (response 0.35, damping 0.85) for state changes; the phase change idle → live morphs the Start
  button into the live header (`matchedGeometryEffect`); Reduce Motion replaces it with a cross-fade. Haptics: selection
  on toggles, success on session start and copy, warning on attention. No decorative animation.
- **Language.** Sentence case, verbs for actions ("Start translating", not "Start live translation"), no jargon on first
  level ("delay", not "OCR→PiP enqueue"; the technical term appears as a subtitle).

### 13.4.2 Components to delete

`infoCard`, `InfoCardModifier`, `ScreenScaffold` (card stacks), `SectionHeader` (uppercase or bold h3 blocks),
`SettingsTile`, `SettingsNavRow`, `SettingsPageHeader`, `LiveStage`, `LiveHero`, `pageBar`/`pageChip`, `HealthRing` as the
first element, `IconButton` circles in toolbars. No old view stays that is not used.

### 13.4.3 Components to build (the only custom ones)

| Component | What it is |
|---|---|
| `LanguagePairTitle` | Two tappable words ("Portuguese ⇄ English") set as a 34 pt title row; the swap glyph sits between them and rotates on tap; tap a word opens `LanguageSheet`. Subtitle line: pack state with icon. |
| `StartButton` | 88 pt circle, accent, system broadcast picker inside; idle shows a slow 4 s breathing glow (static with Reduce Motion); live shows a pulsing ring; doubles as the only filled shape on the idle screen. |
| `LiveCaption` | The translation as large auto-fit text (up to 6 lines), original below at secondary colour (toggle), a three-dot "Reading · Translating · Showing" trail, and a held (pinned) state with a pin glyph. |
| `PhaseHeader` | Glyph + word + timer, e.g. "● Live · 04:12 · Low Latency". Replaces every status pill. |
| `StatLine` | One hero number with caption and sparkline, plus an inline row of two or three secondary values separated by dots (replaces tile grids). |
| `LensRow` | A list row with a title, a one-line live value and a chevron (Diagnostics lenses, Settings groups). |
| `CaptionPreview` | A miniature of the real floating caption (font, size, alignment, background, original on/off) used on Caption, Window and Scene pages and in the Scenes chips. |
| `AreaEditor` | Full-screen editor: a screenshot of the last captured frame (or a sample) with the draggable band, a live "reads X% to Y%" label and Save/Cancel in the bar. |

Everything else is a system component.

## 13.5 Screens

Wireframes are portrait iPhone, 393 pt wide. `[ ]` is a button, `( )` a control, `>` a chevron.

Live (same screen, content morphs):

```

```

- `(⏸)` pause/resume and `(▢)` show/close floating window are labelled toolbar buttons (long labels on VoiceOver and as
  tooltips). Tap the phase header opens the **Session sheet**.
- Focus: full-screen text, controls hide after 3 s, tap to show; text size from the existing reader keys.
- Attention (example: capture lost): the header turns amber with the reason and one action button ("Start again").
- Compose bar: typing opens the result as a card above the bar; Photo and File use the existing OCR path; nothing
  from Text & photos disappears (§12.9).
- Phase morph: the Start button shrinks into the header glyph (matched geometry).
- The tab bar minimises while the caption is full-screen or the Recent list scrolls (`tabBarMinimizeBehavior`, iOS 26 only; guard with `#available`, older systems keep the normal bar).

**Session sheet** (medium detent): state sentence, session timer, translations and characters, Pause, Window, Private
session, Pause after, Clear output, Reopen window, Test the pair, Copy report, link "Open Diagnostics". Technical
timing rows live in Diagnostics only. **Tune sheet**: area (with a `CaptionPreview`-like miniature of the screen and
band), window size, show original, clear when text ends, scene picker, Content and Reading speed menus.

### 13.5.3 Library

Two segments, **Saved** and **Recent** (not "All / Saved / Last 7 days"), `.searchable`. Row: translated text
(headline, 2 lines), original (subheadline, 1 line), trailing time; the language pair is a small footnote, not a capsule.
Swipe: save, delete with Undo. Select mode, export (text/CSV/JSON), restore stay under one "•••" menu. Detail view:
translation large, original secondary, note, actions as a bottom toolbar (Save, Listen, Copy, Share, Picture).
Empty states use `ContentUnavailableView` with one action ("Start translating").

### 13.5.4 Diagnostics

Opens on **one answer**, not a dashboard.

```

 P95 780 ms  ·  126 translations  ·  0 problems    ← StatLine, one row

 Needs attention
 ⚠ Capture isn't running            [Start]       ← only when there is evidence

 Speed        412 ms median                 >
 Timeline     3 events                      >
 Pipeline     Reading 38 · Translating 190  >
 Language     PT → EN · ready               >
 Device       Nominal · 41%                 >
 Memory       3,204 remembered              >
 Test runs    2 saved                       >
 Event log    last: shown caption           >
```

- **No persistent header.** Each lens is a pushed page with its own large title, its own range control if it has
  charts, and a one-line status in the nav subtitle. Nothing from the overview is repeated above a lens (R6).
- **Idle state** shows "No session yet" with the lenses listed and the last saved test run's numbers if any. No health
  score or red colour without a running session (R7). If a health score is kept it appears only after 30 s of live data
  and its page lists what lowered it.
- The mode label shows the mode name only ("Legacy"); the build identifier moves to the About page (R7).
- Charts are full width without a surrounding card, labelled axes, 12 pt minimum labels. "Detailed collection is off"
  is a single inline row with a switch on pages that need it, not a banner on every page.
- Toolbar: Share and a "•••" menu (Detail level, Reset counters, Export ZIP). Every button has a visible or menu label (R10).
- Test runs: the three-system comparison is a small table (Mode · Median · P95 · Captions) with the newest run per mode,
  "Run this mode now" guidance, and the same Save/Report actions as before.

### 13.5.5 Settings

One grouped list, search on top (`.searchable` that finds the setting row itself and opens its page). No brand card
(version is a footer row at the bottom). Five groups:

1. **Translation**: System (Legacy · Hybrid · Low Latency, with explanation), Language packs, Scenes, Memory.
2. **Reading**: Area, Recognition and speed, Text rules and names, Timing.
3. **Floating caption**: Style (font, size, alignment, background, padding, original), Window (size, position).
   Both start with `CaptionPreview`.
4. **App**: Appearance (theme and accent), Haptics and feedback, Reader and photos, Privacy, History and storage, Backup.
5. **Advanced** (collapsed until the switch is on; the switch is the last row of the list): Diagnostics settings,
   Experimental features, Pipeline simulator.

Every settings page: native `Form`, no header card, a `CaptionPreview` or a small diagram where it helps, footers that
explain consequences in plain words, "Reset this page" as the last row. All 109 keys keep their current owner (§12.10
checks).

### 13.5.6 Scenes (presets)

Chips on Translate. Tapping applies; long-press shows Edit, Duplicate, Use at start-up, Delete. Each chip shows its
icon and a `CaptionPreview` thumbnail in the manager. The editor shows a live preview while choosing icon and colour.

### 13.5.7 Onboarding

One screen, three live rows that turn green as they happen: **1 Language pair ready** (picker and Get button inline),
**2 Start a broadcast** (the real picker), **3 Floating window is on screen**. A single "Done" at the bottom becomes
enabled when all three are green; "Skip" is available and the unfinished rows reappear as one "Finish setup" row on
Translate until done.

### 13.5.8 Other screens

Memory, Backup, Experimental, Simulator, Test report: native `Form`s following the page rules above; Memory opens on one
number and a verdict ("3,204 remembered · healthy"), maintenance behind Advanced. Run detail uses the Diagnostics lens
layout (one answer first).

## 13.6 Interaction and accessibility

- Every control labelled; order follows reading order; no information by colour alone; 44 pt minimum targets.
- Dynamic Type up to AX3 without clipping: rows grow, two-column layouts collapse to one.
- Light, Dark, Increased Contrast, Reduce Motion, Reduce Transparency, Bold Text, right-to-left languages checked.
- iPhone SE (375×667), iPhone 16 Pro (402×874), Pro Max, and iPad (single column, max content width 640 pt).
- Landscape: Translate and Focus mode only; everything else portrait-locked as today.
- Destructive actions confirm; reversible ones use Undo toasts.

## 13.7 Systems

- The deployment target is iOS 18.0 (`project.yml`). iOS 26 APIs (`tabBarMinimizeBehavior`, Liquid Glass effects) are used only behind
  `#available(iOS 26, *)` with a plain fallback; every screen must look right on both.

- New view layer in `App/UI/` (screens in `App/UI/<Screen>/`, shared parts in `App/UI/Kit/`). Old files under
  `App/DesignSystem/` (cards, scaffolds, tiles), `App/Live/`, `App/Languages/`, `App/Reader/`, `App/Onboarding/` and the
  replaced parts of `SettingsViews.swift`, `SettingsCategories.swift`, `CustomizationViews.swift`,
  `DiagnosticsDashboard.swift` are deleted when replaced. No dead copies (§12.0.1).
- `SessionPhase` and per-screen snapshot structs live in `App/UI/Model/` and read the engine only through the existing
  narrow-observation mechanism (`EngineSlice`, `EngineFacts`). No new `@Published` on the engine hot path.
- `Strings.swift` keeps all copy; new copy follows §13.4.1 language rules.
- `ThemeStore` and `AppRouter` stay and are extended (`AppTab` becomes `translate, library, diagnostics, settings`;
  deep links `screenlingo://live` and `screenlingo://languages` keep working by routing to Translate and LanguageSheet).
- **Fixtures** (`App/UI/Fixtures/`, compiled only with `SCREENLINGO_FIXTURES`): a `-uiFixture <name>` launch argument
  sets a fake engine state without starting capture. Required fixtures: `idle`, `idle-pack-missing`, `starting`,
  `live-short`, `live-long` (six lines of text), `paused`, `attention-lost`, `library-empty`, `library-many` (200 items),
  `diagnostics-idle`, `diagnostics-live`, `diagnostics-bad`, `settings-root`, `settings-caption`, `languages-sheet`,
  `onboarding`, `area-editor`.

## 13.8 Verification (this is what was missing)

1. **Screenshot job** (`.github/workflows/ui-screenshots.yml`, `workflow_dispatch` and on pull requests that touch
   `App/UI/**`): build Debug for the simulator with `SCREENLINGO_FIXTURES`, then for every fixture × {iPhone SE, iPhone
   16 Pro} × {Light, Dark} × {default text, AX3 text} capture a PNG with `xcrun simctl io booted screenshot` (status bar
   overridden, as `scripts/preview_interface.sh` already does). Upload the PNGs plus one **contact sheet** per device
   (`scripts/make_contact_sheet.py`, one image the owner can open on a phone). The PR description links the run.
2. **Layout lint** (`scripts/test_ui_layout_rules.py`, in CI): fails on `caption2`; `.font(.system(size:` below 12 outside
   `BrandMark`; `infoCard`; a `LazyVGrid` in any `Settings*` file; `.strokeBorder` on surfaces; `.shadow` outside the
   Start button; any `frame(minHeight:` above 120 outside `StartButton`, `LiveCaption`, `AreaEditor`; a `ScrollView`
   whose last child has no bottom inset; more than one `LanguagePicker` implementation; `.preferredColorScheme(.dark)`.
   Each pattern carries its R-number.
3. **Compile before push**: CI cannot be the first compiler. Each commit must build in the workflow; do not stack more
   than one screen per push, and read the CI log yourself when it fails (`gh run view --log-failed`).
4. Existing contract tests (`scripts/test_*.py`, `Tests/*/main.swift`) keep passing; update only for moved symbols.
5. **Owner device check** (not claimed as done by code): list in the PR which items only the owner can confirm (live
   capture, PiP, haptics, tab bar minimise, AX3 on device).

## 13.11 Hard boundaries (unchanged, restated)

Do not edit the bodies of frozen functions in `SampleHandler`, `TranslatorEngine` (`process`, `drain`, `cachedCaption`,
`extractTexts`, `selectBlocks`), `TranslationSystem` or `ModeTranslationService` scheduling. No speed claims without
Diagnostics data from all three modes. Settings keys, defaults and stored formats stay. Privacy stays metadata-only.
If a UI need forces an engine change, stop and tell the owner what and why.
