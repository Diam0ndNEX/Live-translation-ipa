# ScreenLingo 2.8.0 (build 134): capture beside ScreenLingo, one subtitle shown once, less waiting

Branch `claude/screenlingo-v2.8.0` from `main` (2.7.2). Plan: Claude Project doc `v2.8.0-plan.md`. Evidence: device report 2.7.1 build 132 (iPad, 9.9 min, Legacy, pt>en).

**Nothing was compiled or run in chat.** The GitHub Actions run is the first real test. Every effect is UNVERIFIED until a device test (same video, 5+ min, iPhone and iPad, switches on and off). No speed claims.

Owner decisions: no visible quick-then-replace translation; Low Latency is not the main translation for long sentences; early start may ask for less certainty (it stays hidden).

## 1. Capture beside ScreenLingo (switch ownWindowCapture)
Found: the app counted itself on screen in every state except background. On iPad in Split View, Stage Manager or Slide Over the extension then skipped every frame, while the heartbeat kept the link alive, so translation stopped without a message. Likely cause of the 4.5 silent minutes in b132 (unverified: no counter existed).
- App: `TranslatorEngine+OwnWindow.swift` measures ScreenLingo's window in screen fractions each tick and on visibility changes and sends it as `Config.ownWindow` (nil when the switch is off or the app is in the background).
- Extension: pauses only when `OwnWindowCapture.pausesAll` (window unknown, rotated capture, or covering 85 % or more); otherwise reads and drops OCR lines whose centre is inside the window. The app drops packets with the same rule (`ownInterfaceBlocksCapture`).
- Stuck reader: the heartbeat ping carries `readBusyMs` (how long the current OCR read has run, kept behind the heartbeat lock, never the OCR lock). Over 5 s the app shows a status line and counts it.

## 2. Steady translation (switch stableTranslation)
In `show`, after the 2.6.4 check: a new reading of the shown subtitle keeps the shown translation when the new translation is at least 85 % similar (character bigrams), within 6 s, with the same numbers and negation words (source and translation) and at most 20 % more source text. Every reading is still translated; only the redraw is skipped. Counter `translationHeld`.

## 3. Growing subtitles (switch growthPunctuationRelease)
A held growing reading that ends a sentence (. ! ? …) is used at once; the total wait is at most 0.6 s (was 0.9 s). Counter `growthSentenceReleases`.

## 4. Cost-aware early start (switch costAwareEarlyStart)
The learner's required share of first readings that were the final text is 70 % when the median model call is at most 0.15 s, 80 % otherwise (was always 90 %). Early results stay hidden; only an exact match is used. Counter `specTargetMilli`.

## Diagnostics

The four switches are in the report's switches column.
