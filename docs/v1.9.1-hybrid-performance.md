# ScreenLingo 1.9.1 — Hybrid performance, visual continuity and comparable diagnostics

Release candidate: v1.9.1 (build 72)
Base: codex/screenlingo-v1.9.0-three-modes (build 71)
Branch: codex/screenlingo-v1.9.1-hybrid-performance
Status: Code implementation complete; physical-device acceptance remains required. Never merge to main from this workstream.

## Observed problem

Three 1.9.0 build-71 diagnostics exports, collected 29 October 2026 on the same iPhone, showed:
- Legacy: OCR-to-PiP median ~649 ms, P95 ~1026 ms; Apple Default speculative model median ~270 ms.
- Hybrid: OCR-to-PiP median ~834 ms, P95 ~1876 ms; Apple Default speculative model median ~429 ms, Low Latency confirmed median ~984 ms; 37 slow PiP enqueues above 1200 ms.
- Low Latency: OCR-to-PiP median ~324 ms, P95 ~638 ms; speculative model median ~42 ms, confirmed median ~36 ms.

Different test durations, cache history and temperatures limit direct causal attribution. Cross-strategy overlap, retained-session behavior and cancellation correlations are measurable clues, not evidence of which physical model Apple kept resident.

## Architectural findings

Hybrid used Apple Default speculation and explicit Low Latency confirmed recovery in independent sessions. When OCR confirmation could not reuse speculation, the coordinator cancelled speculative work and immediately requested Low Latency recovery. TranslationSession.cancel() is advisory; the earlier request may still occupy framework resources before returning. The model service also refreshed translation-session readiness on every confirmed caption, including checks on both Hybrid session handles, while model inference could be running. Every translation additionally checked installed language availability. These operations risk interfering with the critical path.

The previous preparation code interpreted isReady as a session readiness check, not evidence of actual model residency. v1.9.1 continues that distinction.

## Implemented changes

1. **Adaptive Hybrid scheduling:** Observe whether an early result actually wins selection. After three wasted speculative outcomes, skip five early translation admissions and use the confirmed Low Latency path. Then probe speculation again; a useful speculative selection clears the backoff. Overlapped recovery lasting at least 350 ms triggers the same bounded backoff immediately. This controller affects Hybrid only and is controlled by the existing Adaptive Speculation setting. Legacy and explicit Low Latency keep their own policies. The cold matching-speculation wait is capped at 200 ms instead of 700 ms; this is a ceiling, not an artificial minimum delay.
2. **No redundant per-caption session preparation:** Only check session readiness on initial/changed pair or after invalidation, with a five-second retry guard and no check while backend model work is executing. This prevents two isReady operations for every confirmed Hybrid caption.
3. **Short positive-only language availability cache:** Installed source-target-strategy pairs are reused for 30 seconds; unsupported/uninstalled results are not cached. A translation error invalidates the successful check. Mode-specific language status and downloads from v1.9.0 build 71 are unchanged. When Hybrid's Low Latency pack is known missing, it selects Apple Default recovery directly instead of making two futile fast-model attempts; the backoff controller will not suppress Apple Default speculation in this partial-pack state. Missing optional fast assets cannot display a fatal error when Apple Default fallback remains available.
4. **Explicit backend timing:** Record model service duration, actual strategy overlap, installed-language availability check time, availability cache reuse, task dispatch time, model queue time, cancelled-call release time, and whether an Apple Default or Low Latency request used an existing session. The new full-session stage distributions are independently named; no missing timing is reported as zero-duration inference.
5. **PiP presentation identity:** If a new-mode caption's source, translation, requested original visibility, window size and visual style match an already active PiP frame, do not redraw it. The existing heartbeat continues to keep the frame alive. Event pip_held_unchanged is explicitly separate from pip_enqueue_* to prevent fictitious enqueues, without changing clear/hold behavior or the Legacy pipeline.
6. **Diagnostic event retention:** Preserve early critical mode events plus the recent event tail. Aggregate event counts and stage distributions across the whole session in addition to the bounded privacy-safe timeline. No OCR text, translations, protected names, persistent memory keys or file paths enter the exported diagnostic events.
7. **Tests and upgrade:** Extend deterministic Swift governor tests and Python source contracts. Preserve translation memory, historical records, user settings, and the Legacy code path. Increment app/extension build metadata to 72.

## Acceptance gates before recommending Hybrid

- GitHub macOS Swift compilation, regression suites, diagnostics and Release IPA packaging must succeed.
- Perform cold and warm runs of Legacy, Hybrid and Low Latency on the same iPhone and identical five-minute subtitle segments. Counterbalance mode order, match source/target, speed, OCR area, stability, installed packs, low power, temperature and memory-test policy. Start each Temporary Memory trial with the same baseline and record cache reuse separately. Repeat to assess variation.
- Measure OCR-to-PiP median, P90/P95, confirmed recovery start-to-model-submit, cancellation-to-return, cross-strategy-overlap incidence, new/retained session model service, per-strategy availability-check and dispatch duration, model-memory hits and duplicate-PiP holds.
- Record actual displayed translations on a representative subtitle sample and compare completeness, names, punctuation, speaker labels, corrections and flicker. No quality parity is asserted without this test.
- Look for Hybrid p50 and P95 at least matching Legacy without sacrificing translation quality. Verify acceptable battery, thermals, continuous capture, language-download behavior and stable persisted memory after an in-place install. If these requirements fail, keep Hybrid experimental and preserve Legacy and Low Latency selection.
- An on-device symptom that does not match the diagnosis (for example, slow recovery without overlap or dispatch/availability work) should be investigated from the new per-caption traces before further retuning.

## Known limitations

Apple's public Translation API does not expose model residency or exact internal resource contention. Apple Default is a preferred translation strategy, not proof of the underlying physical model chosen. The capped initial speculation wait and feedback controller are testable heuristics, not a guarantee that Hybrid beats Low Latency. All timing values here are pre-update observations, not v1.9.1 benchmarks.
