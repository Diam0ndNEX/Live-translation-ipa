# ScreenLingo 2.6.1 (build 126): loose memory reuse, session guard, Low Latency abandon, as built

Base: `claude/screenlingo-v2.6.0`. Work branch: `claude/screenlingo-v2.6.1`. Draft PR into the base branch.
**Nothing was compiled or run in chat** (no Swift compiler). All `scripts/test_*.py` were run; pure policies were checked with Python ports. The GitHub Actions run is the first real test.
**Every effect is UNVERIFIED.** No Diagnostics data exists yet for 2.6.0 or 2.6.1.

## 1. Loose memory reuse (switch `looseMemoryReuse`, default ON, report arm `looseMemoryReuseAB`)
- SQLite stays. The schema version stays 2. An additive column `loose_key` (letters and numbers only, lower case, NFC) and index `memory_loose` are added when missing (`ensureLooseKeyColumn`); old rows are filled by `backfillLooseKeys` in batches of 300 after start.
- Order of lookup: exact, then normalized, then loose. Loose runs only when the first two miss and the switch is on.
- A loose hit needs the same language pair, rules and context; ready, persisted rows only; keys shorter than 8 characters never match; two different adapted translations mean `conflict` (a miss); any database error is a miss. The translation takes the closing punctuation of the requested source (`LooseReuse.adapt`). A loose hit is not stored as a new exact entry.
- Counter `looseHits`, report column "reused from a saved variant (2.6.1)".
- Risk: a number or name that differs only in a way the loose key ignores. Digits are kept in the key, so different numbers do not match. Judge quality from the flagged captions.

## 2. Guard (`SwitchGuard`, `TranslatorEngine+Guards.swift`)
Every 5 s: if at least 12 growing-subtitle readings were held and 60% or more were dropped, the growing-subtitle wait (`growthSettle`) is turned off for the rest of the session through `TranslationHotPathAB.sessionOff`. The saved setting is not changed and `pinSettings` clears the guard at the next session start. Recorded as model state `switch_guard_tripped`, counter `guardTrips`, finding `switch_guard_tripped`. Limits are fixed and untuned.

## 3. Low Latency abandon (`ModeTranslationService+Stall.swift`)
With `stallWatchdog` on, a Low Latency call is abandoned 10 s after it starts (the existing 4 s limit only asks the session to cancel). The lane is released as for a failed call: the session is dropped and a new one is created next time. A late result is ignored. This is a plain limit, not the adaptive one used for Legacy.
