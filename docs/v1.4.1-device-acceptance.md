# ScreenLingo v1.4.1: rapid subtitle reliability and device verification

This patch builds on `codex/screenlingo-v1.4.0`; keep `main` untouched. It is intentionally a candidate until the iOS IPA and installed-device regressions pass.

## Why this patch exists

Two same-video build-44 diagnostics (Automatic and Balanced) showed slow first-OCR-to-PiP-enqueue tails, many superseded speculative candidates, and confirmed subtitle work cancelled by newer candidates. The ZIP retention of 600 events covered only tens of seconds; it did not establish actual first-on-screen subtitle arrival, thermal throttling, or physical PiP presentation times. The second run had more previously stored translations and therefore was not a controlled fresh-model speed comparison.

## Changes

- `SubtitleAcquisitionPolicy.changed` distinguishes sparse high-contrast changes from an unchanged image instead of relying exclusively on a whole-screen average. Movie mode forces an OCR refresh within 0.55 seconds of the last OCR start when unchanged-frame skipping is enabled, subject to configured capture cadence. This bounds the unchanged optimization; it is not a guarantee of recognizing all subtitles.
- After eight seconds without useful text, Movie mode applies only a 1.15x recognition-interval multiplier, not 2.5x. Non-Movie modes preserve existing behavior. The idle-backoff toggle is still honored.
- Early OCR for a new candidate can no longer supersede *in-flight, confirmed* output solely on an unconfirmed text change. Once prior output is enqueued, the next early candidate may start normally. A later **confirmed** new candidate still supersedes stale work; do not show old translated text after newer captions have replaced it.
- Speculative work is skipped while confirmed work or the confirmed queue is busy. This protects the translation model from redundant low-priority requests, without promising throughput improvements until device tests.
- A temporary 'Fresh translation test (no memory reuse)' switch bypasses RAM/SQLite retrieval and translate-ahead without deleting the saved database. For a fair fresh-model comparison, run the same video sequence once per mode with this setting enabled and let the device cool between runs. Disable it afterward (it can use more power).
- Remove the obsolete 'Translation memory limit' picker and the unused `memoryCapacity` configuration. History, RAM cache, SQLite, and diagnostic sample controls remain independent and saved translations are untouched.
- New diagnostic counters: capture frames/OCR passes, cadence/unchanged/paused skips, empty reads, contrast retries, first confirmed packets, speculative deferrals, superseded unpresented confirmed candidates and enqueued frames.
- Event ring expanded to 2400 recent structured events. Correct allowlisting for OCR execution/completion. Add metadata-only records for capture connection/heartbeat loss, idle auto-pause, session timer and thermal-state transitions. Export remains text-free and bounded.

## Validation

- `Tests/main.swift` covers visual-change sensitivity, forced refresh, idle policy and confirmed-caption lifecycle.
- `Tests/DiagnosticArchive/main.swift` validates OCR labels and bounded most-recent event export. Existing privacy/redaction tests remain.
- GitHub Actions must pass macOS pipeline/SQLite/diagnostics regressions and unsigned IPA build. Inspect each run at the exact **final** head SHA. A prior run/partial workflow is not proof that the final integration builds.
- An unsigned IPA requires external signing before a device can install it. An installed in-place update must preserve Application Support, history, settings and SQLite memory. Do not uninstall the existing app to upgrade.

## Device acceptance

1. Keep existing SQLite contents. Disable 'Fresh translation test' for the normal-use test. Use Movie mode, the actual subtitle crop and the same video.
2. Watch the start of playback, the first subtitle after >8 seconds without text, short consecutive subtitles, scene cuts and almost-static video where only subtitle glyphs change.
3. Record **seen in video vs OCR acquired vs confirmed vs enqueued**, distinguishing true misses from deliberately stale candidate suppression. Export diagnostics *immediately* after unexpected stalls.
4. Run with unchanged-frame skipping enabled and disabled one at a time; do the same for idle backoff. Track missed subtitle rate, p50/p95/p99 and temperature/thermal transitions.
5. For mode-to-mode speed benchmarking, enable 'Fresh translation test' in both runs. Run a second normal-use test with memory enabled, because disabling reuse intentionally does not represent typical performance.
6. Verify PiP does not show stale or out-of-order captions and there is no unexpected pause, capture disconnect, retained-memory loss or UI freeze.

### Remaining limitations

This update does not measure the exact first visible subtitle video frame or physical screen presentation, and therefore cannot guarantee a zero-miss subtitle rate. Confirmed new candidates still take priority over old confirmed translations when the scene changes. Real-device installed-upgrade, thermal/power and complete long-session tests are mandatory before claiming production readiness.
