Base: `claude/screenlingo-v2.5.6`. Work branch: `claude/screenlingo-v2.6.0`. Draft PR into the base branch.
**Nothing was compiled or run in chat** (no Swift compiler). All `scripts/test_*.py` were run; the pure policies were checked with Python ports. The GitHub Actions run is the first real test.
**Every effect is UNVERIFIED.** No report has ever captured a stall, and the quality signals are proxies.

## 1. Stall recovery (switch `stallWatchdog`, default ON, report arm `stallWatchdogAB`)
Owner report: after a while the app stops translating; a capture restart sometimes helps, otherwise only an app restart.
- **Code finding (read, not run):** `drain()` sets `busy` and awaits `process`, which awaits the model call in `runBatch`. The call had no time limit. `busy` is cleared only when the call returns, so a call that never returns blocks all translation while the capture keeps delivering frames. Cancelling the drain task does not release a call that ignores cancellation.
- **`ModelCallRace`** (`Shared/TranslationSystem+V260.swift`): a live (non-warm-up) call runs in its own task and is abandoned when it does not return within the limit; a late result is dropped and widens the limit. The existing stream and `translations(from:)` calls are unchanged (they moved into `performModelCall`).
- **Limit** (`ModelStallLimit`): 6 times the P95 of the last 50 successful calls, between 6 and 30 s; 15 s before 5 calls succeeded. A call abandoned and later returned adds its length to the sample.
- **After an abandoned call** `runBatch` returns nil; the existing retry per sentence uses a new session (the direct session is dropped on a nil result, a lent session is dropped by `returnLent(usable: false)`).
- **Lane watchdog** (`TranslatorEngine+Stall.swift`, once a second from `tick`): when confirmed work waits and no model call started or ended for max(8 s, limit + 3 s), `StallLadder` gives one step at a time, 10 s apart: lane reset (new drain epoch, `busy` cleared, new drain) then session reset (direct session and speculative owner reset) then local link reset (`server.restart()`) then "unhealthy" (toast; repeat from the first step after 60 s). Progress (no queued work) resets the ladder and records the stall length.
- **Counters and table "Stalls (2.6.0)":** calls abandoned, returned later, lane/session/link resets, unhealthy, stalls that ended, stall length P50/P95. Findings `model_call_hung`, `lane_stall_recovery`, `translation_service_unresponsive`, `capture_restarts`.
- **Not covered:** the Low Latency lane (`ModeTranslationService`) was not read and has no watchdog. A hung Apple translation service may not be recoverable inside the app. A late return of an abandoned drain can in theory present an old caption (its generation checks still apply).

## 2. Automatic findings and the verdict
`DiagnosticArchive+IssueSignals.swift` adds findings from counters (stalls, growth held and dropped, text-block joins, memory hit rate, pixel rejection rate, heat). Fixed thresholds are stated in each explanation and were not tuned on device data. The report starts with "0. Verdict and flags" (stop-related flags first). Nothing is marked by hand.

## 3. Automatic quality signals (proxies)
`CaptionSignals` (`Shared/TranslationSystem+Quality.swift`, pure) checks every shown caption from the text alone: the same sentence shown again within 8 s; a caption that starts like one shown within 4 s but differs (rewritten); translation equal to the source; a number of 2+ digits missing; length far from this run's learned ratio (30 samples, 3 sigma, sigma at least 0.25); a word repeated 3 times in a row. Counters and table "Automatic quality signals". No speaker label, punctuation, language or layout rule.
A flagged caption is saved by the app as text (`FlaggedCaptionStore`): at most 200, removed after 14 days, not in a private session, a repeat of the same translation within 5 s is not saved again, 600 characters per text. `Include flagged captions' text in reports` (`flaggedCaptionText`, default ON, Experimental) controls both saving and the last report section "9. Flagged captions (text)". **This is the only subtitle text in any report;** the report header says so and counts the notes. Whole-session text never leaves the phone. Open owner decision: keep the default ON?

## 4. Memory miss classification (measurement only)
`LooseUnitIndex` (`Shared/TranslationSystem+MissClass.swift`) says, for each confirmed unit that missed memory, whether it is new, differs only in case/punctuation/spacing from a unit already seen in this run (near miss), or is the same unit seen earlier but not in memory. Counters `missNew`, `missNearMiss`, `missRepeatedExact` and a report table. Two lines in `process` (recorded in `test_three_modes.py` L2_UNDO as measurement-only). Nothing is reused differently.

## 7. Planned in the 2.6.0 plan but NOT built here
Per-caption record and worst-N retention; run segmentation independent of capture start and stop; first-OCR wait measurement; regression flags against earlier runs and bootstrap intervals; guardrails that switch off a harmful switch inside a run; CI replay fixtures beyond the growth-tracker cases; idle shadow check; Memory loose reuse, quarantine and staleness identity (they need a schema change that CI must test first); content profile, progressive display, thermal curve. Reasons: recorder internals were not read, and these touch schemas or hot paths that cannot be verified without a compiler.
