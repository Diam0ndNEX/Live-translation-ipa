# ScreenLingo v1.7.0 (54): normal-model performance candidate

Improve overall speed/latency using normal translation in Balanced, without worsening
wording, completeness, order, flicker or reliability. Low-latency is not a substitute.
Device acceptance is pending; code, CI and simulation cannot establish a 90% device win.
Base: v1.5.0 build 53, commit 5637617115e6b7c30abdaf8dcd8305f9278c499a.

## Changes

- Saved-memory reuse no longer queues redundant durable saves. Tentative disk hits
  retain their origin until confirmed reuse. Exact language/rule/model/name keys remain.
- Sentence saves coalesce for 75ms using the existing FULL-durability transaction.
  Explicit/background flush bypasses the delay. Pending entries are not acknowledged
  before commit. Existing queue bounds, retries, storage-full and revision checks remain.
- Reuse only the two indexed read-only lookup statement shapes on the SQLite actor.
  Reset and clear bindings after every call, including conflict/timeout/error exits;
  finalize on recovery/teardown. No row-result cache or quarantine bypass.
- Duplicate exact keys within one processing pass share lookup outcomes. No persistent
  negative cache and no broadened normalization or fuzzy reuse.
- Recover complete obsolete confirmed batches into bounded exact-context RAM, as
  already done for speculative batches. Never directly present or persist old work.
  Fresh-test, context/rule/language invalidation and incomplete batches reject recovery.
  Separate counter: completedConfirmedUnitsRetained.
- Drain tasks explicitly use user-initiated priority. Retain the single-model drain
  and confirmed-before-speculative ordering; no competing live model sessions.
- Suppress capture of ScreenLingo's own foreground interface, preserving heartbeat
  transport and the previous caption. Both processes reject old work across visibility
  boundaries and restart confirmation outside the app. Manual text/photo paths remain.
  Outside-app time is not proof of video playback. Performance settings provide an
  opt-out for a video floating over ScreenLingo. The suppression switch is exported;
  comparison against older unsuppressed runs requires matching it (off) to prevent
  passing the gate by merely removing own-app navigation work.
- Model durations use an independent bounded 1200-sample collection. High-frequency
  event eviction no longer selectively removes model durations. Not all-time data.

No model swap, reduced OCR detail/correction, narrowed crop, relaxed confidence,
fewer confirmation reads, fuzzy reuse or incomplete-caption presentation.
Experimental controls keep their stored values and default to off.

## Verification and acceptance

macOS CI runs pipeline, SQLite migration/fault/recovery, real UDP transport,
diagnostic archive privacy/correlation, settings checks, storage benchmark, Release
iOS app/extension compilation, metadata verification and IPA packaging. Added tests
cover visibility config compatibility/reset, reused bindings across hit/miss/
quarantine/clear and the comparison gate. Authoring Linux has no Swift/Xcode/iPhone.

Run `python3 scripts/compare_performance.py BASELINE.zip CANDIDATE.zip --quality-evidence checks.json`.
The matrix is fixed before device results: 10 stages x median/mean/P90/P95 = 40 cells.
Stages: enqueue latency, all OCR, final OCR, confirmation, queue, processing,
delivery/filtering, rendering, memory lookup and model batch. At least 20 samples
per distribution; missing data never shrinks the denominator. A win is strictly
lower, a tie is not a win; at least 36/40 wins and no missing cells are required.

Both runs must use normal models/Balanced, matching device, OS and recorded settings.
Regressions in enqueue/model failures, expired handoffs or confirmed superseded before
enqueue veto acceptance, as does worsened memory health. Some older exports cannot
fill the full matrix; do not invent their missing data. Compare each eligible baseline,
not only the easiest. Report P99/max separately despite exclusion from the fixed score.

The quality JSON must explicitly attest all fields true after human review:
same_video_and_boundaries, comparable_memory_and_startup, wording_no_worse,
coverage_no_worse, order_no_worse, flicker_no_worse,
long_session_reliability_no_worse, thermal_and_battery_no_worse.
No default/generated attestation is supplied. The score alone cannot prove quality.

Repeat matched clips with cold and warm memory, controlled startup and experiments
off. Previous whole-session exports included navigation; v1.7.0 suppresses own-app
OCR. Repeat old baselines with matched playback boundaries before attributing an
improvement to processing. Never trim failures silently or average bucket percentiles.

## Required device checks

1. Same five-minute video and quality inspection, normal Balanced, same settings/packs.
2. Cold/warm normal-memory replay, restart reuse, no redundant save on disk hits.
3. App switches/export: no interface-text loop, stale work or artificial reconnect;
   source capture resumes and valid previous captions remain during navigation.
4. Rapid captions, growing blocks, names/slang/lyrics, language/rotation changes:
   recovered work cannot display stale or partial text.
5. Private/fresh-test sessions, clear/quarantine during work, suspension during
   coalesced saves, storage-full/retry/restart durability.
6. iOS 18 hosted and iOS 26 direct translation, missing packs/model failure, low power,
   heat and long-session behavior. Cancellation is cooperative.

## Primary research

- SQLite statement reuse avoids preparation work: https://www.sqlite.org/cintro.html
- Reset does not clear bindings and its status matters: https://www.sqlite.org/c3ref/reset.html
- Apple batch responses require request identity: https://developer.apple.com/documentation/translation/translationsession/translate(batch:)
- Cancelling a session invalidates future requests: https://developer.apple.com/documentation/translation/translationsession/cancel()

Keep the normal-model memory namespace, request text and quality settings unchanged.
Scheduling/reuse can hide model time; they cannot promise the low-latency model's
cold execution time. No 90% pass or physical-device quality parity is claimed.
