# ScreenLingo 2.5.4 (build 122): Legacy waits less for confirmation, as built

Base: `claude/screenlingo-v2.5.3`. Work branch: `claude/screenlingo-v2.5.4`. Draft PR into the base branch. Owner rule: Low Latency is never the default; Legacy keeps the Apple Default model and the same wording.
**Nothing was compiled or run in chat** (no Swift compiler there). Swift was read and edited as text; all `scripts/test_*.py` were run. The GitHub Actions run is the first real test.
**No speed improvement is claimed.** Every effect is UNVERIFIED until Diagnostics on the same video shows it.

## 1. Evidence (2.5.2 build 120 report, Legacy, 5 sessions, pt>en, plus the trace by script)
- Mean OCR to PiP 646 ms (S2 to S5), median 498. About 150 ms of it is one OCR read; the wait for confirmation averages 330 ms (54% of captions need more than 230 ms, mean excess over one read about 190 ms).
- 477 of 1915 captions (25%) confirmed slowly (over 300 ms) and had no early translation at all (475 first calls were confirmed-lane); their total median was 946 ms. The model was busy at text-known time for only 32% of them. An early call started when the text was first read would have been ready about 300 ms sooner (ceiling 75 ms on the mean over all captions).
- "More than the line limit" was the top reason for a second OCR read (51 to 71% of extra reads per session) although 2.5.1 raised the limit to 8. The check fingerprints every line read from the whole area, so unrelated text on the screen switched it off. An extra read costs about 170 ms.
- Code: `SpeculationPolicy.credible` asked for confidence 0.85 on every line of the packet (all lines the capture found), so one low-confidence line anywhere vetoed an early translation. The report could not say which gate blocked the 25%; the counters exist in the export but were not in the report.

## 2. Changes
| Change | Switch | Default | Quality |
|---|---|---|---|
| L1. Pixel check covers up to 24 lines (`PixelConfirmation.manyLinesMaximum`, was 8). Up to 8 lines the rule is unchanged (global tolerance, cap 16). Above 8, each line is judged on its own ink (tolerance 1 to 16, at least 1), so a changed line cannot hide among unchanged ones. A rejected check falls back to a normal OCR read exactly as before. `samplePoints(lines:allowMany:)`, `matchesPerLine`. | Pixel check for up to 24 lines (new), both modes | ON | Same text read and translated; same evidence per line or stricter; ink contrast, tolerance, minimum ink and dwell unchanged |
| L2. Legacy: whether a first reading may start an early translation is judged on the lines whose text is part of the text to translate (`CaptionLineSelection.indices`, `speculationJudgedLines`), not on every line of the packet. Used in `handleContent` and in `speculateBehindActiveCaption`. When no line matches, all lines count (2.5.3 behaviour). The 0.85 limit, the adaptive window and every other rule are unchanged. | Early translation judged on caption lines (new), Legacy | ON | None: same model and wording; an early result is used only when the confirmed text has the same units |
| L4. Report: "Why a first reading got no early translation (2.5.4)": low confidence, adaptive low yield, adaptive saved reuse, model busy, same text as before, behind the shown caption (whole-session counts from existing counters). Report "switches on" names the two new switches; archive allowlists have `manyLinesAB`, `captionLinesAB`. | none | always | none |
Both switches are pinned at session start with the others (`v254Switches`), shown in Experimental features (and reset with its reset button) and in the Diagnostics test-switch line.

- Version asserts in eight other scripts: 2.5.3/121 to 2.5.4/122.
- Swift (compiled only in CI): `Tests/main.swift` (24 lines fingerprinted when allowed, 25 not, nine still not by default, per-line tolerance), `Tests/HotPathAB/main.swift` (switch defaults, one switch off alone, `CaptionLineSelection`).

## 4. Risks
- L1: more captions confirm from pixels. A caption that changes in a way the sampled grid misses would be confirmed one read early (the same limit the classic check has for up to 8 lines). Turn the switch off if wrong or half-faded text is shown.
- L1: up to 24 x 384 luma samples per check (about 9,000 reads, every 30 ms at most while a check is pending). Expected well under 2 ms; not measured.
- L2: more early translations (heat, contention with confirmed calls; early calls already stop at Serious and Low Power). The 2.5.2 run had 56 of 69 early calls belong to a shown caption.
- L2 uses a letters-and-digits match between a line and the text to translate; a line rewritten by the block step is treated as not part of it and not judged.

## 5. Not changed (open)
The wait before the first OCR read (OCR cadence 0.25 s, early wake only after 0.18 s and at most twice per second) is not in the report and was not touched. Option O1 (confirm on the first read when the pixel check already shows the text unchanged) was not built: it lowers confirmation evidence and needs its own decision after this test. Long captions (161+ characters) and heat are unchanged.
