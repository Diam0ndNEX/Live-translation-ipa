# ScreenLingo v1.4.0 — real-device acceptance protocol

Status: **NOT VERIFIED** until an installed-IPA upgrade and long-running on-device tests pass.
This document is a release gate, not evidence that the tests have been completed.

## Installation and migration (P0)
1. Record the previous IPA's displayed version, bundle identifier, signing profile,
   date, device model, and iOS version. Keep the old IPA available for rollback.
2. Install an older supported version **without changing the app container**.
   Set a source/target pair (for example Portuguese → English), translate at
   least 20 distinct phrases and several repeated subtitles, and confirm the
   prior memory counter. Record History and Settings values.
3. Install signed v1.4.0 **over the installed app** with the same bundle ID and
   compatible signing entitlement. Do not uninstall first.
4. Open Settings → Translation memory; record schema version, migration state,
   total/ready/needs-validation/conflict counts, last verified snapshot, failed
   writes, and database size. Expect no silent deletion of preexisting files.
5. Repeat the same stable subtitles. Only verified compatible entries may count
   as persistent/legacy hits. Old opaque keys must remain preserved even when
   excluded from automatic reuse. Verify History and Settings are intact.
6. Close/relaunch, then repeat. Install another later build over v1.4.0 and
   repeat the retention/restart checks. Check that clearing RAM **does not**
   delete committed translations.
7. Export a manual memory backup and verify integrity. Check that the export
   includes text and must be treated as sensitive. Import it into an isolated
   test installation; do not overwrite the user's sole source of memory.
8. Record actual results and attach redacted diagnostic JSON only after
   confirming the privacy controls. Do not share raw subtitles unnecessarily.

**Important:** Uninstalling an app can delete its sandbox. Bundle-ID changes or
incompatible signing may create another sandbox. This test proves only an
in-place upgrade of the verified installation path.

## Playback, OCR and integration regression (P0)
On the same device, test Movie mode; then Fast, Balanced, Sharp and Automatic
recognition on the same static and scrolling examples. Test Instant, Normal
and Careful stability; automatic rotation, skip-unchanged, multilingual input,
language correction, speculative confirmation, duplicate subtitle copies,
scrolling lyrics, pause/resume and frozen PiP. Verify that late old-candidate
results cannot replace a newer subtitle. Record symptoms, frame IDs, and trace
reason codes where available; do not infer translation quality from counters.

## Controlled latency and energy (P0)
Use the same device, iOS version, language model assets, language pair, mode,
settings, source frames, brightness and similar initial thermal state for
both versions. Measure repeated subtitles, entirely fresh subtitles, mixed
workloads, and long sessions. Export p50/p95/p99, sample count and session
window for OCR, memory lookup, fresh translation and PiP enqueue. Compare
like-for-like samples only; physical display latency is not instrumented.
Monitor battery level, low-power mode, thermal state, RAM growth, dropped
frames and visible PiP stutter. A GitHub macOS benchmark is **not** evidence
of iPhone latency or power consumption.

## Diagnostic privacy and recovery (P0/P1)
- Confirm Basic/Detailed/Developer modes obey text capture consent, do not
  store raw screen images, and do not automatically upload anything.
- Confirm JSON/TXT/CSV exports and optional ZIP contain no source text by
  default; memory backup is explicitly different and **does contain text**.
- Test the memory Settings controls: search, category counts, conflict
  inspection, quarantine, import/export, verify integrity and snapshot creation.
- Test independent deletion: History, persistent memory, and diagnostics must
  remain independent. The option to erase preserved memory copies is
  destructive; first secure an external backup.
- Only in a disposable test container: verify that recovery rejects an invalid
  snapshot; restore a known verified snapshot after deliberate corruption.
  Confirm damaged SQLite, -wal and -shm are preserved in quarantine and note
  that translations newer than the backup may not appear until salvaged.
- Test backgrounding/suspension with pending confirmations. The app may report
  pending work; do not interpret a queued write as successfully committed.

## Results to retain
Record exact app commit SHA, GitHub workflow run, device/iOS identifiers,
installation method, number of remembered entries before/after upgrade,
migration state, History and Settings retention, repeat-hit counts, latency
sample sizes and p50/p95/p99, device/thermal observations, and all failures.

**Release policy:** A successful unsigned IPA CI artifact alone is not an
on-device acceptance. Keep PR #5 as a draft and avoid merging into main until
this protocol is executed and regressions are resolved.
