# ScreenLingo v2.0.0 §11: Test Runs (rebuild of diagnostic session saving)

Part of the 2.0.0 specification (`docs/v2.0.0-specification.md`), §11. Written 2026-11-07.
Branch `claude/screenlingo-v2.0.0`, draft PR #34 into `codex/screenlingo-v1.9.9-recovery-evidence`. Never `main`.
Version: **2.0.0 build 84** (2.0.0 has not been device-tested or released; bump the build, keep 2.0.0,
unless the user asks for 2.0.1).

Nothing here is compiled or run. CI is the first real test. Every finding in §11.1 comes from **reading** code,
not from running it; the size estimate is a calculation, not a measurement.

## 11.0 What the user asked for

"I tried saving one of the tests, it doesn't work. I have never really used the manual or automatic saving system.
Completely redesign and re-engineer it and every system that interacts with it, from the ground up, and update the
UI and UX, before I test again."

Goal: a test of the three modes (Legacy, Hybrid Recovery, Low Latency) must save itself reliably, one saved run per
broadcast per mode, with clear feedback, and export as one report. Saving must never slow translation or take the
memory database with it.

## 11.1 Why saving fails today (read in code, not reproduced)

Code read: `Diagnostics.swift` (`persistSession`, `loadSessions`, `deleteSessions`, `tick`, `reset`, `sessionSnapshot`,
sessions page, `TestReportSheet`), `DiagnosticArchive.swift` (`encode`, `redact`, `encodeIndexedEvents`,
`TranslationModeReport.sanitized`, `CombinedDiagnosticReport`), `TranslationMemoryStore.swift`
(`saveDiagnosticSession`, `loadDiagnosticSessions`, `clearDiagnosticSessions`).
Not read: `TranslatorEngine.swift` (who calls `diag.reset()`), `HomeView.swift`, `SettingsViews.swift`, `scripts/test_*.py`.

**Verification before build 84 (read in code, not run):** F2, F3, F4, F6, F7 and F8 confirmed. F1 and F5 confirmed from the call
site and the store code (`saveDiagnosticSession` rejects payloads over 1 MiB; the call runs on the memory store actor);
the size estimate itself is still unmeasured. Corrections and additions:
- `diag.reset()` is called from only three places in `TranslatorEngine.swift`: `testModeSettingsChanged()`,
  `diagnosticsSettingsChanged()` (through `collectionChanged()`) and `resetDiagnostics()`. So toggling the test cohort or
  diagnostics collection also ended a "session" (F4), and so did the old `persistDiagnosticSessions` toggle in Settings.
- `HomeView`: the test tiles were shown only when `persistDiagnosticSessions` was on, so with the default (off) there was no
  Save run button at all (F2/F8).
- `persistDiagnosticSessions` was also listed in `PipelineSimulation.swift` and asserted by `scripts/test_experimental_settings.py`.
- `mode_trace_ring_overwritten` is only reported through `session_*` keys, so F6 hid the truncation warning completely.
- Mode events are accepted only for the epoch `diag.started` of their session (`modeDiagnosticEpochs`), so every run boundary
  that clears the collection must refresh that epoch; the engine does this.
- `saveDiagnosticSession` stays in `TranslationMemoryStore.swift` because `Tests/MemoryStore` still exercises it; the app no
  longer calls it.

F1. **Size cap makes every real session fail (most likely cause).** `saveDiagnosticSession` rejects payloads over
1 MiB (`MemoryStoreError.tooLarge`). `DiagnosticExportWriter.encode` writes **pretty-printed** JSON with up to 2,400
structured events (3–5 UUIDs each), up to 2,400 mode-trace events (two 64-char hex strings + UUID each), 300 one-second
buckets and 180 five-second buckets (≈90 counters each). Estimate: 2–4 MB for a 5-minute detailed session. The error
only shows "Session could not be saved".
F2. **Silent no-ops.** `persistSession()` returns without any status when diagnostics are off, the toggle
`persistDiagnosticSessions` is off, a private session is on, another save is running, or the store is nil. "Save now"
is disabled when the toggle is off; Home "Save run" calls the same function.
F3. **Lost saves.** The 30-second autosave in `tick` and the save in `reset()` both skip while `archiveInProgress`
is true, so the final save at a session boundary can be dropped.
F4. **Wrong session boundaries.** A session runs from one `diag.reset()` to the next, not from broadcast start to stop.
It can span several broadcasts and several modes, but is labelled with the mode active at save time
(`translationModes.active`). The combined report then picks "the newest session of each mode" from mislabelled data.
F5. **Saving competes with translation.** Diagnostics are stored in the translation memory SQLite file, on the same
actor that serves the 8 ms memory lookups, with `synchronous=FULL`. A multi-MB transaction every 30 s during a broadcast
can delay lookups (timeouts) inside the measured run. `sessionSnapshot()` also builds the whole snapshot on the main
actor every 30 s.
F6. **Data dropped on save.** `TranslationModeReport.sanitized()` runs twice (in `sessionSnapshot` and again in
`redact`). The second pass looks up raw reason keys that the first pass already renamed to `session_*`, so whole-session
mode counters and distributions are lost. The combined report's truncation line reads `session_mode_trace_ring_overwritten`
and so always shows 0. Separately, `redact`'s `allowedMetrics` omits keys that `sessionSnapshot` emits
(`hybridMatchingWaitMs` is kept, but `hybridUnsubmittedHedgeMs`, `hybridPreviousDefaultExitGapMs`,
`hybridPostDefaultRecoveryServiceMs`, `hybridNoOverlapRecoveryServiceMs`, `hybridUnexplainedSlowRecoveryMs` are dropped).
F7. **Surprising side effects.** "Delete saved diagnostic sessions" turns the save toggle off. Saved sessions expire
after 7 days, are capped at 20 and 10 MB, and the oldest are deleted without notice.
F8. **UI.** Saving is hidden in Diagnostics → Sessions; saved items are titled only by start time; no mode, duration,
content or result is shown; no rename, pin or per-item delete.

## 11.2 New model: Test Runs

- **Run** = one broadcast in one translation system: starts when capture connects, ends when capture stops, when a
  pending mode change is applied, when the user resets diagnostics, or when the app is terminated. A run never mixes modes.
- **Test** = a named group of runs (e.g. "2.0.0 test 1"). The current test is shown on Home; new runs join it.
  "New test" starts a new group. The report exports one test.
- **Run record** (metadata only, same privacy as today): id, test id, mode, start/end, duration, end reason,
  app version/build, device model, iOS, language pair, preset, speed, memory cohort, effective recognition switches,
  experimental toggles, thermal states seen, starting RAM entries, user label (optional, ≤40 chars, e.g. "Video A"),
  pinned flag, completeness (complete / recovered / trimmed + what was trimmed), plus the redacted snapshot.

## 11.3 Saving

- Setting **Save test runs**: `Automatically` (default) · `Only when I tap Save` · `Off`. New key `testRunSaving`.
  Migration from `persistDiagnosticSessions`: true → automatic, false/missing → automatic (the old toggle was never used
  successfully). Remove `persistDiagnosticSessions` from the snapshot allowlists and settings.
- Automatic: every run of ≥ 30 s with ≥ 1 PiP enqueue is saved when it ends. Shorter runs are discarded with a visible
  note ("Run too short to save – 12 s").
- Manual: **Save run** saves the current run (as a checkpoint, run continues) or the last ended run if it was not saved.
- Private session: runs are not saved; Home shows "Private session – runs are not saved".
- Every save returns a typed result shown to the user: `saved`, `skipped(reason)`, `failed(reason)`. No silent return.
  Reasons are fixed codes (privateSession, savingOff, tooShort, noData, diskFull, encodeFailed, writeFailed).
- **Crash safety:** a checkpoint every 60 s during a run. On the main actor only capture copy-on-write state (target
  < 1 ms; measure it and record `run_checkpoint_capture_ms`); build, redact, encode, compress and write on a background
  actor. At launch, a leftover checkpoint becomes a run marked "Recovered (incomplete)".
- No autosave work during a run other than the checkpoint. Remove the save from `Diagnostics.tick` and `reset()`.

## 11.4 Storage (out of the memory database)

- New `TestRunStore` actor. Folder `Application Support/TestRuns/`: one file per run `run-<uuid>.json.lzfse`
  (compact JSON, no pretty printing, LZFSE via `NSData.compressed(using:)`), plus `index.json` (run metadata only, for
  the list without decoding payloads), plus `run-<uuid>.partial` checkpoints. Atomic writes, file protection
  `completeUntilFirstUserAuthentication`, excluded from backup.
- No 1 MiB rejection. If an encoded run is over 8 MB, trim in this order and record it in the run: one-second buckets,
  then the oldest structured events, then the oldest mode-trace events. Never fail a save for size.
- Retention: pinned runs are never deleted automatically. Unpinned: keep the newest 40 and ≤ 100 MB total; delete the
  oldest beyond that and show it in the list footer ("2 older runs removed to stay under 100 MB"). No age expiry.
- Migration: at first launch of build 84, read existing `diagnostic_sessions` rows once, convert them to runs marked
  "Imported (mode may be mixed)", then stop writing to those tables. Do not drop the tables in this release.
  `TranslationMemoryStore` keeps `loadDiagnosticSessions` for the migration only; remove `saveDiagnosticSession` callers.
- Translation memory actions (clear, export, import, snapshots) never touch runs, and run actions never touch memory.

## 11.5 Data fixes

- Sanitize the mode report once. `sessionSnapshot` builds raw data; `redact` sanitizes. Test that `session_*`
  counters and distributions survive save → load → report.
- Single allowlist source: derive `allowedMetrics` from the keys `sessionSnapshot` emits (shared static list). Test that
  every emitted key survives redaction.
- Run-level boundaries replace `diag.reset()` as the session boundary. Live diagnostic views may still reset for display,
  but a reset during a run ends the run (with end reason `diagnosticsReset`) and starts a new one.
- Record per run: mode at start and every applied mode change (should be none), so the report can flag mixed runs.

## 11.6 UI and UX

Home (Live tab), one **Test** card under the mode switch (§10):
- Current test name (tap to rename) and a three-mode checklist for it: Legacy / Hybrid / Low Latency, each ✓ with
  duration and median when a saved run exists, and "Next: Low Latency".
- While broadcasting: "Recording run · Hybrid · 3:12 · 54 captions".
- After a run ends: banner "Run saved · Hybrid · 5:02" with **Rename**, **Pin**, **Undo** (delete); or the skip/fail
  reason in orange.
- Buttons: **Save run** (manual mode, or to checkpoint now), **Clear test memory** (existing behaviour), **Export report**.
- Replace the separate `HomeToolTile`s from §9 with this card.

**Test Runs** screen (from the Test card and Diagnostics; replaces Diagnostics → Sessions):
- Grouped by test, newest first. Row: mode icon and name, label, start time, duration, captions (n), OCR→PiP median/P95,
  thermal, badges (Pinned, Recovered, Imported, Trimmed, Filled memory at start, Mixed mode).
- Swipe: Delete, Pin. Edit mode: multi-select → Export report, Delete. Footer: storage used / limit.
- Run detail: summary numbers, warnings, settings that differ from the other runs in the test, actions: Export report
  (this run), Export ZIP, Rename, Pin, Move to test, Delete.
- Export report: defaults to the current test, newest run of each mode preselected; up to 6 runs; the existing
  `CombinedDiagnosticReport` builds the file, now including run label, test name, end reason and completeness.
- Deleting runs never changes any setting.

Settings → Diagnostics: the **Save test runs** picker, storage used, "Delete all unpinned runs".

## 11.7 Code changes (expected)

- New `App/TestRunStore.swift` (actor: index, save, load, delete, pin, rename, prune, checkpoint, recover, migrate).
- New `App/TestRunViews.swift` (Test card, Test Runs list, run detail, report sheet; replaces `TestReportSheet`).
- `Diagnostics.swift`: run lifecycle (`beginRun`, `checkpointRun`, `endRun(reason:)`, `saveRunNow()` returning a result),
  copy-on-write capture, remove `persistSession`/autosave/`archiveInProgress`, replace sessions page.
- `DiagnosticArchive.swift`: compact encoder for storage (keep pretty JSON only inside ZIP exports), single sanitize,
  shared metric allowlist, report fields for test/label/end reason/completeness.
- `TranslatorEngine.swift`: call `beginRun`/`endRun` at capture connect/stop, mode change applied, diagnostics reset,
  scene background/terminate. Read every `scripts/test_*.py` check that names a function before editing it; this file
  has frozen-function contract tests.
- `TranslationMemoryStore.swift`: migration read only; no new diagnostic writes.
- `HomeView.swift`, `SettingsViews.swift` / `SettingsCategories.swift`: new card and picker.
- `Shared/Shared.swift` + `project.yml` (3 places each): build 84, changelog entry; update every CI script that asserts
  the version or the old key names (`persistDiagnosticSessions`, `persistSession`, `saveDiagnosticSession`).

## 11.8 Tests

New `Tests/TestRuns/main.swift` (wired into CI like the other Swift test targets):
- Save/load round trip of a synthetic 5-minute run at full caps (2,400 + 2,400 events, 300 + 180 + 20 buckets):
  saves, compressed size printed, under 8 MB without trimming.
- Oversize run is trimmed in the documented order and marked trimmed; never rejected.
- Retention keeps pinned runs; prunes oldest unpinned by count and size.
- Checkpoint → simulated relaunch → recovered run.
- Migration from `diagnostic_sessions` rows (fixture) → imported runs.
- Save results: private session, saving off, too short → the right `skipped` reason.
- `session_*` mode counters survive save → load → report; every `sessionSnapshot` metric key survives redaction.
- A run never contains two modes; mode change mid-run ends the run.
- No text fields leak (same check as `Tests/DiagnosticArchive`).

## 11.9 Device acceptance

- With default settings, run Legacy, Hybrid, Low Latency on the same video: three runs appear automatically in the
  current test with the right modes; export report preselects all three.
- Force-quit the app during a run: next launch shows a recovered run.
- Private session on: Home says runs are not saved, and none is saved.
- Memory lookup `timeout` counts are not higher than in build 83 runs (saving no longer shares the memory database).
- No speed claim from this work. Translation latency must not regress beyond noise in any mode.
