# ScreenLingo 1.4.6 (50)

Based on verified 1.4.5 head 37c503c0e8157b84f5f6a7b7771092848135b494.

## Legacy validation

An exhausted cursor previously remained exhausted after changing language/rules.
The engine now fingerprints the selected pair, processing rules, database counts
and known installed model set. Changes reset the cursor/exhaustion on the next
five-second scheduling check. Active validation is never reset mid-batch.
Manual rescan explicitly restarts the scan. Capture/PiP, power/thermal, privacy,
foreground and transactional safety gates remain unchanged.

The last-scan inventory partitions pending legacy rows into different target,
different source, outside 4–240 characters and scan candidates. Candidates are
not a promise of eligibility: scan reasons separately count unreadable/contextual
keys, cleanup/slang changes, sentence-unit changes and unavailable models.
Reasons cover the latest scanned batch, not the entire database. Inventory is
read-only and runs only when idle validation is allowed, not during live lookups.
No originals are deleted or trusted without fresh independent model evidence.
Multi-sentence/context-sensitive records still require review; this release does
not claim to make every remaining record automatically validatable.

## Latency

Confirmed input that differs exactly from the in-flight speculative input now
cancels that tentative drain; the existing single-drain unwind starts confirmed
work without concurrent writes to pipeline state. Matching speculative input can
finish for exact reuse. Cancellation remains cooperative; obsolete results are
rejected even if the model finishes later. Partial cache reuse opportunities may
be reduced, so compare queue delay and model workload on-device.

Failed tentative translation batches now yield instead of retrying every sentence
while a confirmed job waits behind the shared drain. Confirmed translation keeps
its existing retry/failure behavior. Successful pretranslation is unchanged.
This is a scheduling optimization on a failure path, not a claim of reduced
median latency in every workload. Recognition detail, confidence, required reads,
whole-caption assembly, memory-key compatibility and language selection remain.
No diagnostics-screen/interface text classifier is added, per user instruction.
Startup test conditions differed in prior runs; no causal speed claim is made.
